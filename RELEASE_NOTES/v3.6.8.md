# Release Notes: v3.6.8 - Fix SDXL ConvRot INT8 black images on the stock CheckpointLoaderSimple path (ComfyUI v0.44)

Version **v3.6.8** fixes the black-image failure that appeared after the
**ComfyUI v0.44.0 update**, when an SDXL **ConvRot INT8** checkpoint is loaded
through the **stock `CheckpointLoaderSimple`** node, and repairs the
`PromptServer.instance` compatibility crash exposed during the investigation.
Fix commit `00bc498`.

---

### What the failure looked like

Sampling completed normally - the workflow reported success - but the decoded
image was **completely black**. The exact same workflow on an FP16 checkpoint
produced a normal image, which made the failure INT8-specific. It appeared
right after the ComfyUI update.

### Measured root cause (layer-by-layer hook probes)

Instrumenting a single `apply_model` forward outside ComfyUI (sigma=10,
y=zeros, 64x64 latent, fixed seed) located the failure precisely:

| layer | measured output |
|---|---|
| `input_blocks.2.0` conv1 (INT8 path) | mean -86.6, **std 858.6**, max 3984 |
| `input_blocks.2.0` out_conv | mean 38.7, **std 475.0**, max 2530 |
| `input_blocks.3.0.op` (quantized Conv2d) | **out = inf** (first inf in the model) |
| `input_blocks.4.0.in_layers.0` (GroupNorm) | **out = NaN (all 327,680 elements)** |
| DiT final output | **all 163,840 elements NaN** |

The CLIP text encoder was measured healthy at the same time, so the failure
was DiT-side only.

The decisive measurement compared the loaded weight of
`model.diffusion_model.input_blocks.3.0.op` with what the disk actually
contains:

| source | dtype | std |
|---|---|---|
| correct dequant (int8 x `weight_scale`) | fp32 | **0.02229** |
| **what the loader produced** | **fp16** | **29.255** |

That is a **~1300x** per-channel inflation (matching `1/weight_scale_i`) - the
int8 values were never multiplied by `weight_scale`.

### Why ComfyUI v0.44 does this

ComfyUI's own `MixedPrecisionOps` has **never had a Conv2d class** (verified
against both v0.42.5 and v0.44.0 via git history - it only defines
`Linear`, `MoEExperts`, `Embedding`). The HSWQ quantized Conv2d is injected
into that ops class **only while the INT8 conv scope is open**, and the scope
is only opened by the loader-specific load paths - never by
`comfy.sd.load_checkpoint_guess_config`, the path the stock node calls
directly. Under v0.44 the conv weights therefore loaded as raw int8 values
cast to fp16, activations overflowed fp16 inside the network, and the whole
forward collapsed to NaN.

### The fix

`_patch_checkpoint_loader_simple_int8_scope()` (patches/comfy_quant_int8.py)
wraps `comfy.sd.load_checkpoint_guess_config` and opens `_int8_quant_conv_scope()`
around the load **only when the checkpoint is an SDXL/SD1.5-style INT8 pack**
(detected by block keys via `checkpoint_needs_hswq_int8_conv2d`). Inside the
scope, the loader's `mixed_precision_ops_force_conv` injects the HSWQ
quantized Conv2d whose `_load_from_state_dict` builds a genuine
`QuantizedTensor`/`TensorWiseINT8Layout` weight with the scale and ConvRot
metadata intact and rotates activations online. The wrapper installs at
import time (`_hswq_ensure_loader_scope_at_import()`), so it is active for
any stock CheckpointLoaderSimple load. Checkpoints without the SDXL/SD1.5
block keys (Krea2, FLUX/DiT, MOSS) bypass the wrapper untouched. **ComfyUI
core is not modified.**

The same commit also restores the benign pre-init behaviour of
`server.PromptServer.instance` reads (3 sites now use
`getattr(server.PromptServer, "instance", None)` in
`model_management_mgpu.py`), because ComfyUI no longer defines that attribute
at class definition time.

### Measured after the fix

| quantity | before | after |
|---|---|---|
| `op.weight` type | fp16 Parameter (int8 raw values) | QuantizedTensor / TensorWiseINT8Layout |
| `_hswq_convrot` | absent | True |
| Conv2d class | stock manual_cast (`module comfy.ops`) | HSWQ Conv2d (`module …patches.comfy_quant_int8`) |
| DiT forward output | all NaN (163,840/163,840) | mean -0.0344, std 0.7010, nan 0, inf 0 |

FP16, Krea2, FLUX/DiT, and MOSS workflows are unchanged; the interfaces of
every other loader are preserved (separation maintained - ComfyUI core is not
modified).
