# Release Notes: v3.7.0 - Full LoRA & LoKr (Kronecker product) support for ConvRot INT8 & Hybrid NVFP4 models (Z Image & Krea2) and upstream WeightAdapter adaptation

Version **v3.7.0** brings **complete, robust LoRA and LoKr (LyCORIS Kronecker product) support** to both **Z Image (Hybrid ConvRot NVFP4 and ConvRot INT8)** and **Krea2 (ConvRot INT8)** models, fully adapting to ComfyUI's architectural migration to `comfy.weight_adapter` (`WeightAdapterBase`, `LoRAAdapter`, `LoKrAdapter`).
Code commit `0882fce`. Full technical guide: [md/v3.7.0_COMPLETE_EXPLANATION.md](https://github.com/ussoewwin/ComfyUI-HSWQ-Loader-and-Tools/blob/main/md/v3.7.0_COMPLETE_EXPLANATION.md).

---

### Failure modes resolved

1. **Silent LoRA Failure (Zero Effect) on Quantized Models**:
   - Stock ComfyUI patching attempts to dequantize weights, add LoRA deltas, and re-quantize back to 8-bit or 4-bit.
   - Typical LoRA deltas ($0.1\% \sim 0.8\%$ of weight maximum) are far smaller than the coarse quantization step ($\approx \text{amax}/127$ for INT8, even coarser for NVFP4), causing round-to-nearest re-quantization to round deltas to zero.
   - In addition, `MixedPrecisionOps.Linear` sets `want_requant=False` and `_dit_quant_lock` skips dequantization from Step 2 onward, leaving resident weights completely unpatched.

2. **Tensor Shape Mismatch Crash on Krea2 LoKr Models**:
   - Running popular Krea2 LoRAs (such as `realism_engine_krea2_v3.1.safetensors` or `babegenerator.ink-realism_helper.safetensors`) crashed immediately inside the DiT attention block:
     ```text
     RuntimeError: mm: mat1 and mat2 shapes cannot be multiplied (11363x6144 and 1536x1536)
       at nodes/krea2_convrot_int8/int8_forward.py, line 85, in _add_krea2_lora_residual
       term = torch.matmul(torch.matmul(inp, md.t()), mu.t())
     ```

3. **DisTorch2 / MultiGPU Invalidation**:
   - When running under DisTorch2 (upstream `comfyui-multigpu` or HSWQ variants), `ModelPatcher` cloning severed dynamic residual attributes or replaced patched forward functions, causing multi-GPU pipelines to silently drop LoRA applications.

4. **Krea2 Load-Time UnboundLocalError Crash**:
   - `patches/comfy_quant_int8.py` crashed immediately on INT8 checkpoint load:
     ```text
     UnboundLocalError: cannot access local variable 'apply_comfy_quant_int8_patches' where it is not associated with a value
     ```

---

### Root cause & technical mechanism

- **ComfyUI `WeightAdapterBase` Migration**: Upstream ComfyUI refactored all LoRA structures into object-oriented adapters. LyCORIS Kronecker product LoRAs are instantiated as `LoKrAdapter`, whose weights tuple carries factor matrices:
  $$\text{weights} = (w_1, w_2, \alpha, w_{1\_a}, w_{1\_b}, w_{2\_a}, w_{2\_b}, t_2, \text{dora\_scale})$$
  with $w_1 \in \mathbb{R}^{4 \times 4}$ and $w_2 \in \mathbb{R}^{1536 \times 1536}$ ($4 \times 1536 = 6144$). Legacy code treated $w_2$ as a down-projection $[1536, 1536]$, causing a dimension collision against the $[11363, 6144]$ input.
- **ConvRot Basis Parity**: ConvRot weights are pre-rotated via an orthogonal Hadamard matrix $H$ ($W_{\text{rot}} = W H^T$). Directly adding unrotated LoRA deltas $\Delta W$ to $W_{\text{rot}}$ corrupts the orthogonal basis. The delta must be evaluated in the native weight basis and accumulated into the unrotated layer output:
  $$Y = \text{Linear}_{\text{ConvRot}}(x) + \Delta W(x)$$
- **Python Scope Shadowing**: An inner import inside `load_unet_hswq_weight_dtype` shadowed the module-level `apply_comfy_quant_int8_patches` under Python LEGB rules, turning it into an unbound local variable when the enclosing branch was skipped.

---

### What the loaders now do

1. **Native LoKr Residual Extraction**:
   - `_extract_lora_residual` (Krea2) and `_extract_zi_lora_residual` (Z Image) detect `adapter_name == "lokr"`, extracting factor matrices $w_1$ and $w_2$ while supporting factorization products ($w_{1\_a} w_{1\_b}$ and $w_{2\_a} w_{2\_b}$).
   - Standard LoRA weights (`lora`) undergo rigorous shape validation, verifying $\text{mat\_up.shape}[1] == \text{mat\_dn.shape}[0]$.

2. **Fast Grouped Tensor Product Forward for Kronecker Factors**:
   - Rather than materializing the dense $6144 \times 6144$ matrix (which would require $>8.4\text{ GB}$ of temporary VRAM across 112 DiT projections), HSWQ exploits the tensor identity:
     $$(W_1 \otimes W_2) \cdot \text{vec}(X) = \text{vec}\left(W_2 X W_1^T\right)$$
   - Input $X \in \mathbb{R}^{B \times L \times (q \cdot s)}$ is reshaped to $[B, L, q, s]$ ($q=4, s=1536$), executing chained cuBLAS matrix multiplications:
     $$H_b = X_{[B, L, q, s]} \cdot W_2^T \quad \in \mathbb{R}^{B \times L \times q \times r}$$
     $$H_c = \left(H_b^T \cdot W_1^T\right)^T \quad \in \mathbb{R}^{B \times L \times p \times r}$$
     $$\text{Term} = \text{Reshape}(H_c, [B, L, p \cdot r])$$
   - Temporary VRAM overhead is virtually zero, running at sub-millisecond tensor-core latency.

3. **Zero-Loss Floating-Point Delta Forward**:
   - Base quantized weights (INT8 / NVFP4) remain 100% frozen bit-exact inside VBAR/mmap storage.
   - Extremely subtle LoRA deltas ($0.01\% \sim 0.1\%$) are completely preserved against quantization rounding to zero, providing true FP16/BF16 expressiveness alongside full quantization memory savings.

4. **DisTorch2 / MultiGPU Parity**:
   - Bound forward methods and residual containers survive `ModelPatcher` clones, ensuring every GPU computes and injects its local exact floating-point residual across tensor/pipeline parallel slices.

5. **Load-Time Scope Fix**:
   - The inner import in `patches/comfy_quant_int8.py` is aliased to `apply_krea2_convrot_int8_patches`, eliminating the `UnboundLocalError`. Also added `covrot` typo fallback detection.
