# Release Notes: v3.6.9 - Quantized Conv2d support for ControlNet models

Version **v3.6.9** brings **quantized Conv2d support for ControlNet models** to
both HSWQ loaders (`HSWQ ControlNet Loader` and `HSWQ Model Patch Loader`).
Until now every ControlNet pack kept its conv weights in FP16, which capped the
size reduction; when a checkpoint actually carries quantized Conv2d layers, the
loaders now inject the HSWQ quantized Conv2d (rotation along in_channels,
per-out-channel scale `[out, 1, 1, 1]`, online activation rotation).
Code commit `ede3f1b`.

---

### Why ControlNet packs stayed large

The loaders quantized 2D `nn.Linear` weights only; ComfyUI's stock INT8 path
has no quantized Conv2d, so every conv weight stayed FP16. A 3x3-conv-heavy
SD1.5 ControlNet is dominated by that half: the recolor pack carries
**61 Conv2d weights = 440.57 MiB, 63.9 % of the source file**. The Linear half
alone shrank 44 % (248.1 MiB → 138.5 MiB), but the whole-file reduction was
capped at **15.9 %** (722,598,616 B → 607,603,903 B).

### What the loaders now do

The pack format for a quantized conv is the same one the SD-UNet INT8 path
already uses: rotation along in_channels, per-out-channel scale
`[out, 1, 1, 1]`, `convrot_groupsize` 256, online activation rotation done by
the injected Conv2d.

**Detection** - `_has_int8_comfy_quant_conv2d()` (added to both
`nodes/hswq_load_convrot_int8_controlnet.py` and
`nodes/hswq_model_patch_loader.py`) returns True only when an
`int8_tensorwise` `comfy_quant` layer sits on a 4D weight. Packs whose
quantized layers are all Linear take the previous load path byte for byte.

**Injection** - for such a checkpoint the loaders build `custom_operations`
**inside** `_int8_quant_conv_scope()` and apply `_patch_ops_decode_and_conv()`
explicitly. Both steps are required: without the explicit patch the ops class
carries no Conv2d at all, and without the scope the injected class is skipped -
in both cases the int8 payload is read as a plain float Conv2d. Measured with
the payload read as float: output cosine mean **-0.1142** / min **-0.1739**,
rel L2 3.1e12 - destroyed. Because a silent miss is that destructive, a failed
patch now **raises and stops the load** instead of passing.

### Measured on the SD1.5 recolor pack (Conv2d 24 of 61 quantized)

| measurement | value |
| :--- | :--- |
| pack size | 607,603,903 B → **411,127,471 B** (**43.1 % reduction**, −187.4 MiB) |
| load route | declared 77 / INT8 77 / **not applied 0** → `applies` |
| output difference vs source (4 batches, seed 42) | cosine mean **0.9996957** / min **0.9996680**, rel L2 max 0.0264760 |
| Linear-only pack for comparison | cosine mean 0.9997190 / min 0.9996969 (the conv half costs 2.3e-05 of cosine for 187.4 MiB) |
| 256-item acceptance gate | mean **0.999861** / min **0.999834** / p5 0.999849 → **PASS** |
| rendered frame | 1024x1024, 12 steps, 636 INT8 GEMM calls, latent finite, inspected - no artefacts |

The other 37 conv modules keep FP16: their in_channels are not divisible by
the group size (256), so a Hadamard rotation cannot be applied to them.

### Compatibility boundaries

- Linear-only ControlNet packs load unchanged: the existing canny pack
  measures `applies` 53/53 exactly as before (regression measured).
- The Qwen-Image model patch path loads unchanged (602 tensors, regression
  measured).
- ComfyUI core is not modified; only checkpoints that carry quantized Conv2d
  layers enter the new path.
