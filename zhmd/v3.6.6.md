# v3.6.6 发版说明（中文）

## 概述

**CLIP 文本塔现已跑真正的 INT8 GEMM。** ComfyUI 的 `int8_tensorwise` 算法声明为 `quantize_input: False`，属于 **weight-only** 格式：权重虽以 int8 留在显存，但每次矩阵乘都会先 dequant，真正的 INT8 GEMM（`comfy_kitchen` 的 `int8_linear`）根本走不到。因此 ConvRot INT8 CLIP pack 只拿到了 int8 权重的显存收益，却要付出 fp16 GEMM 的算力代价 —— 文本编码实测比 FP16 基线**慢 1.9 倍**。

本次发版把 INT8 GEMM 接入 CLIP 文本路径。**ComfyUI core 未作任何修改**：由加载器包在 import 时安装 runtime arm。

CLIP ViT-L/14 实测（RTX 5060 Ti，batch 1，11 轮 CUDA event 计时取中位数，两次独立运行复现）：**INT8 stock 路径 27.77 / 26.37 ms，`int8_linear` 调用 0 次** -> **启用 arm 后 19.53 / 19.74 ms，`int8_linear` 调用 73 次**（相对 stock 路径 **-29.7 %**），对应 **FP16 参照 14.05 / 14.56 ms**。

---

## 技术架构与实现细节

### 1. 根因：weight-only 算法 + 被关闭的量化矩阵乘
共有两重机制把 INT8 GEMM 挡在 CLIP 文本塔之外：
- **量化矩阵乘被关闭**：`comfy/sd1_clip.py` 以 `mixed_precision_ops(quant_config, dtype, full_precision_mm=True)` 构建文本编码器。`full_precision_mm=True` 会使 `MixedPrecisionOps.Linear.forward` 中的 `_use_quantized` 为 false，激活值同样不会被量子化。
- **weight-only 分支会 dequant**：即使打开量化矩阵乘，`forward_comfy_cast_weights` 的 weight-only 路径仍会在 `F.linear` 前把权重 dequant。结果是用 int8 体积跑 fp16 GEMM —— 收益只在显存，绝不在算力。

### 2. Runtime Arm（`patches/clip_int8_gemm/arm.py`）
该 arm 由包的 `__init__.py` 在 import 时安装，只触碰两处调用点：
- **包装 `comfy.ops.mixed_precision_ops`**：传入 `quant_config` 的调用方拿到 `full_precision_mm=False`，从而使用量化矩阵乘。
- **包装 `MixedPrecisionOps.Linear.forward_comfy_cast_weights`**：`TensorWiseINT8Layout` 权重不再被 dequant，而是连同在线 ConvRot 激活旋转一起交给 `int8_linear`。
- **作用范围**：仅 `TensorWiseINT8Layout` 层走新路径，其他 layout 全部保持 stock 行为；包装是幂等的，重复安装不会叠加。

### 3. 补全缺失的 `text_projection`
CLIP-L checkpoint 可能不带 `text_projection`。在 stock（dequant）路径下无害，但 INT8 GEMM 会带着 `None` 权重走到该投影，前向以 `'NoneType' object has no attribute 'device'` 崩溃。arm 在加载时以 fp16 零矩阵补全；该故障在本次发版前已复现并修复。

### 4. 全部已发布 CLIP pack 的验证
按单次 encode 统计 `int8_linear` 调用次数，确认全部已发布 CLIP pack 均已走 INT8 GEMM：

| CLIP pack | 每次 encode 的 `int8_linear` 调用 |
|---|---|
| `clip_l_hswq_convrot_int8` | 70 |
| `ViT-L-14-BEST-smooth-GmP-HF-format_hswq_convrot_int8` | 64 |
| `Long-ViT-L-14-BEST-GmP-smooth-ft-full_hswq_convrot_int8` | 73 |

## 基准实测

CLIP ViT-L/14，RTX 5060 Ti，batch 1，11 轮 CUDA event 计时取中位数。FP16 与 INT8 在同一进程内交替轮次测量，使 GPU 频率漂移对两方影响一致；整套测量另在第二次独立运行中复现（每格两个值为第 1 次 / 第 2 次运行）：

| 指标 | FP16 | INT8（stock 路径） | INT8（启用 arm） |
|---|---|---|---|
| **编码延迟** | 14.05 / 14.56 ms | 27.77 / 26.37 ms | **19.53 / 19.74 ms** |
| **每次 encode 的 `int8_linear` 调用** | - | **0** | **73** |
| **相对 FP16** | 1.00x | **慢 1.9 倍** | **慢 1.35 倍** |
| **arm 带来的增益** | - | - | **-29.7 %** |

保真度，在固定 256 条验收集合（seed 42）上对比 FP16 基线实测：

| 指标 | INT8（stock 路径） | INT8（启用 arm） |
|---|---|---|
| **cos mean** | 0.999792 | 0.999712 |
| **cos min** | 0.999641 | 0.999548 |
| **cos p5** | 0.999711 | 0.999616 |

该微小变化是动态激活量化的预期代价，两者都远高于验收阈值。pack 仍保持 ConvRot INT8 权重布局，体积不变：**文件 1631.80 MB -> 413.20 MB**，常驻权重 **235.90 MB -> 118.48 MB**。

## 向后兼容

- **CLIP ConvRot INT8 pack**：arm 对每次量子化 CLIP 加载都会安装，既有 pack 无需重新生成即可获得 INT8 GEMM。
- **ComfyUI core**：未作任何修改。arm 完全位于本包的 `patches/clip_int8_gemm/` 内，且仅对 `TensorWiseINT8Layout` 权重生效。
- **其他模型家族**（SDXL / SD1.5 / Z Image / Krea2 / SAM3）：加载路径不受影响；arm 只拦截 CLIP 文本塔的 `Linear` 类。
- **非量子化 CLIP**：stock 路径原样保留，仅在传入 `quant_config` 时才改变 `full_precision_mm`。
