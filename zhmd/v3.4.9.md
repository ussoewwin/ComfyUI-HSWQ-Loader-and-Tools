## 1. 概述

**v3.4.9** 为 **HSWQ ControlNet Loader (`HSWQControlNetLoader`)** 引入了**动态计算 Dtype 解析机制（Dynamic Compute Dtype Resolution）**，全面解决了在缺乏原生 `bfloat16`（BF16）硬件 Tensor Core 支持的 **NVIDIA Turing 架构（RTX 2000 系列、GTX 1600 系列、Tesla T4）** 及更早 GPU 上的潜在崩溃与性能劣化问题。

在保持量化 INT8 权重严格以 **8-bit 精度（`QuantizedTensor` / `TensorWiseINT8Layout`）** 驻留显存（VRAM）的同时，周边模块图、非量化层及中间激活张量将根据主机 GPU 硬件特性自动适配最佳计算精度（Ampere / Ada / Blackwell 采用 `torch.bfloat16`；Turing / Pascal 采用 `torch.float16`）。

---

## 2. 技术背景：Turing (sm_75) 架构的 BF16 硬件限制

### 硬件架构差异
- **Ampere / Ada / Blackwell（SM 80、89、100、120+）**：具备原生第 3/4/5 代 Tensor Core，提供对 `bfloat16` 的完整硬件加速支持。
- **Turing（SM 75 —— RTX 2060/2070/2080、GTX 1660、Tesla T4）**：具备对 `FP16` 和 `INT8` 的原生 Tensor Core 支持，但**不具备 `bfloat16` 的硬件计算单元**。

### 硬编码 BF16 带来的问题
在早期版本（v3.4.4–v3.4.8）中，`HSWQControlNetLoader` 为解决 PyTorch 对 INT8 张量的梯度初始化崩溃问题，将模块图构建与 `MixedPrecisionOps` 的计算 dtype 强制设定为 `torch.bfloat16`。在 RTX 3000/4000/5000 系列上表现优异，但在 Turing 架构上会引发以下问题：
1. **运行时崩溃**：部分 CUDA GEMM 内核与算子抛出 `RuntimeError: "addmm_cuda" not implemented for 'BFloat16'` 或 cuBLAS 不支持的数据类型错误。
2. **隐式 FP32 升精度与显存膨胀**：PyTorch 无法在硬件上执行 BF16 算子时，会隐式将中间激活及非量化层（LayerNorm、zero_convs、bias 等）升精度至 `torch.float32`（4 字节/元素）进行软件模拟，导致中间显存开销翻倍并大幅降低计算速度。

---

## 3. 架构设计与动态解析实现

`HSWQControlNetLoader` 现已集成 ComfyUI 标准设备查询接口（`comfy.model_management.should_use_bf16()`），在加载模型时自适应确定最优计算精度。

```
                  [ safetensors Checkpoint ]
                               │
                               ▼
                   [ _has_int8_comfy_quant ]
                    /                     \
        (未检测到 INT8)               (检测到 INT8)
                  /                         \
    [ 原生 ControlNet 路径 ]      [ _get_default_compute_dtype() ]
    (FP16/BF16/FP8 自动穿透)                 /               \
                              (SM >= 80: Ampere+)    (SM <= 75: Turing/Pascal)
                                     /                         \
                            torch.bfloat16                  torch.float16
                                     \                         /
                                      ▼                       ▼
                                 [ _int8_mixed_precision_ops ]
                                 [ 以对应 dtype 构建模块图 ]
                                               │
                                               ▼
                              [ VRAM: TensorWiseINT8Layout (INT8) ]
                              [ comfy_kitchen int8_linear 执行推理 ]
                                               │
                                               ▼
                                      [ CONTROL_NET 输出 ]
```

### 核心实现组件
1. **动态 Dtype 选择器 (`_get_default_compute_dtype`)**：
   ```python
   def _get_default_compute_dtype(device: torch.device | None = None) -> torch.dtype:
       """Ampere/Ada/Blackwell 等现代 GPU 选择 BF16；Turing/Pascal 等旧架构选择 FP16"""
       if device is None:
           try:
               device = comfy.model_management.get_torch_device()
           except Exception:
               device = None
       if comfy.model_management.should_use_bf16(device=device):
           return torch.bfloat16
       return torch.float16
   ```
2. **自适应 `MixedPrecisionOps` 绑定**：
   - `_int8_mixed_precision_ops(compute_dtype)` 将硬件匹配的浮点 dtype 注入 `mixed_precision_ops`。
   - 对于 ConvRot INT8 模型（如 Qwen Image Fun ControlNet、FLUX ControlNet），权重在显存中保持 `TensorWiseINT8Layout`，而非量化算子与在线激活旋转在 Turing 上以原生 FP16 执行，在 Blackwell/Ada/Ampere 上以 BF16 执行。

## 4. 硬件支持与精度矩阵

| GPU 架构 | 代表型号 | 计算 Dtype | 权重显存保持 | 激活 / 非量化层 Dtype | 硬件 Tensor Core GEMM |
|:---|:---|:---:|:---:|:---:|:---:|
| **Blackwell (SM 100/120)** | RTX 5090, B200 | `torch.bfloat16` | INT8 (8-bit) | BF16 (16-bit) | 原生 (`comfy_kitchen` `int8_linear`) |
| **Ada Lovelace (SM 89)** | RTX 4090, RTX 4080 | `torch.bfloat16` | INT8 (8-bit) | BF16 (16-bit) | 原生 (`comfy_kitchen` `int8_linear`) |
| **Ampere (SM 80/86)** | RTX 3090, A100 | `torch.bfloat16` | INT8 (8-bit) | BF16 (16-bit) | 原生 (`comfy_kitchen` `int8_linear`) |
| **Turing (SM 75)** | RTX 2080 Ti, RTX 2060, GTX 1660 | `torch.float16` | INT8 (8-bit) | FP16 (16-bit) | 原生 FP16 Tensor Cores + INT8 权重 |
| **Pascal (SM 60/61)** | GTX 1080 Ti, Titan X | `torch.float16` | INT8 (8-bit) | FP16 (16-bit) | 支持 (FP16/FP32 回退) |

---

## 5. 向后兼容性与工作流影响

- **完全零破环性**：节点名称（`HSWQControlNetLoader`）、别名（`HSWQLoadConvRotINT8ControlNet`）、输入端口（`control_net_name`）与输出类型（`CONTROL_NET`）100% 保持不变，已有工作流无需做任何修改即可直接无缝运行。
- **传统模型兼容性**：非量化 FP16、BF16 及 FP8 ControlNet 检查点继续通过自动探测并走 ComfyUI 原生 `load_controlnet_state_dict` 流程。
- **FLUX 原生布局支持**：具备 ConvRot INT8 量化的 Comfy 原生 `ControlNetFlux` 布局同样继承动态计算 Dtype 解析。
