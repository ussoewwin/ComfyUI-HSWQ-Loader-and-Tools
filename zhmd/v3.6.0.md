# v3.6.0 发布说明（中文）

## 概述

**Krea2 ConvRot NVFP4 支持已终止。** `Krea2 ConvRot NVFP4` `weight_dtype` 选项已从 UNet 加载器移除，且 Krea2 NVFP4 加载/前向运行时已删除：3 个纯删除文件（783 行）+ 8 个 NVFP4 专用模块（1,984 行）被移除，3 个保留模块被剥离（合计 2,124 -> 1,099 行）。剩余的 Krea2 运行时已从 `nodes/krea2_convrot_nvfp4/` 重命名为 `nodes/krea2_convrot_int8/`，现仅服务 **Krea2 ConvRot INT8**（stock INT8 forward + 低秩 LoRA 残差）。此外，v3.5.8 中 `attention_accel` 组件已被移除后遗留的 SageAttention2 模块（`hswq/hswq_sa2_accel.py`，423 行）也已删除。

**SDXL ConvRot INT8、SDXL ConvRot NVFP4、Z Image INT8、Z Image ConvRot NVFP4 逐字节无变化** —— 以 git blob 哈希对比 `v3.5.9` 与 `v3.6.0` 标签间 `nodes/nvfp4/`、`nodes/zimage_nvfp4/`、`nodes/sdxl_int8/` 及 INT8 loader 节点共 27 个文件：零差异。

> **不再支持加载 Krea2 ConvRot NVFP4 检查点。** 仍带有 `Krea2 ConvRot NVFP4` 值的已保存工作流可无崩溃执行（加载器通过 `**kwargs` 吸收未知关键字参数并回退到 INT8 / default 路径），但曾为其服务的 NVFP4 专用加载栈已删除。Krea2 继续通过 **ConvRot INT8** 支持 —— 它是唯一在 DisTorch2 加载器下验证过的 `weight_dtype`。

## 技术细节

### 1. 为什么被移除的代码对 Krea2 ConvRot INT8 是 no-op（基于证据）

每条被移除的路径都以 INT8 加载路径从不设置的 NVFP4 专用状态为门控（对照 `v3.5.9` 的 git 源码实测，非凭记忆）：

- NVFP4 加载路由：`if is_nvfp4_conf(conf) and (has_nvfp4_scale or dtype == uint8)` —— INT8 包携带 `int8_tensorwise` conf 与 int8 存储，始终落到 `_orig_load`。
- `convert_weight` / `set_weight` ConvRot wrap：以 `getattr(self, "_hswq_nvfp4_convrot", False)` 为门控 —— 该旗标仅由已退役的 Krea2 NVFP4 arm 路径设置。INT8 在线激活旋转走 `patches/comfy_quant_int8.py`（独立机制），从未经由这些 wrap。
- packed-K / txtlayers 检测修正：作用于 NVFP4-packed projector/Linear 存储（`weight_scale_2`）；INT8 包不受影响。
- addmm 处理器 / TC 门控 / kitchen 修复 / FP4 gemm / 运行时池：全部以 `TensorCoreNVFP4Layout` 为键；INT8 张量使用 `TensorWiseINT8Layout`。
- NVFP4 第一遍 bake：INT8 包上候选数为 0（无 NVFP4 层），移除不改变 INT8 bake 结果；INT8 残差遍（`bake_remaining_quant_patches_on_dynamic_patcher`）原样保留。

### 2. 共享 peel 协议保持不变（SDXL / Z Image 共存）

Krea2 mp wrap 保留了 SDXL（`nodes/nvfp4/`）与 Z Image（`nodes/zimage_nvfp4/`）peel walker 读取的共享标记：`_hswq_nvfp4_stack_ver = 2`、`_hswq_nvfp4_orig_mp`、`_hswq_nvfp4_full_forward`，以及 forward 解包用的闭包名 `stock_forward`。Krea2 专用标记由 NVFP4 更名为 INT8（`_hswq_krea2_stack` 保留；`_hswq_krea2_nvfp4_pack` -> `_hswq_krea2_int8_pack`；`_hswq_krea2_nvfp4_lora_bake` -> `_hswq_krea2_int8_lora_bake`），且 `patches/comfy_quant_int8.py` 与 `patches/hswq_purge_rearm.py` 中的 setter / getter / purge 门同步更新（实测：旧名残留 0 件）。

### 3. 已执行的验证（全部实测）

- **SDXL / Z Image 0 字节证明**：对 27 个文件（`nodes/nvfp4/`、`nodes/zimage_nvfp4/`、`nodes/sdxl_int8/`、INT8 loader 节点）执行 `git rev-parse v3.5.9:<path>` 与 `HEAD:<path>` 对比 —— blob 哈希全部一致。
- **AST import 符号检查**：变更及依赖模块中 141 个相对 import 符号逐一对照模块级定义 —— 0 问题。
- 全部变更 Python 文件 `py_compile` —— 全部 OK。
- 加载器源码含 0 处被删选项字符串；live（`custom_nodes`）树逐文件校验：93 个 Python 文件与仓库哈希一致。

## 更新方法

通过 ComfyUI Manager 更新，或直接在 `custom_nodes/ComfyUI-HSWQ-Loader-and-Tools` 目录拉取：
```bash
git pull
```
重启 ComfyUI 生效。重启后 UNet 加载器下拉菜单不再出现 `Krea2 ConvRot NVFP4`，**Krea2 ConvRot INT8** 加载（含低秩残差 bake 的 LoRA）与 v3.5.9 行为完全一致。一如既往地，在所有 HSWQ 工作流末尾放置 **General Purge VRAM V2** 并开启 `HSWQ` 开关。
