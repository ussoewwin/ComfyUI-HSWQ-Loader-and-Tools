## ① 问题是什么

### 症状

在使用 tcon（Z Image TC/W4A4）NVFP4 模型的工作流中，**第 1 次生成正常**，但**在 DisTorch HSWQ purge 之后，第 2 次生成完全变成噪声**。

### 日志证据（bake 结果对比）

| 生成次数 | Bake 结果 | 状态 |
|------|-----------|------|
| 第 1 次 | `nvfp4_baked=86 int8_baked=94` / `NVFP4_LORA_BAKE_OK` | 正常 |
| 第 2 次 | `nvfp4_baked=0 other_qt_baked=83` / `NVFP4_LORA_BAKE_N/A` | NVFP4 层被误判为 `other_qt`，未做 ConvRot 即被 bake → 噪声 |

第 2 次日志中的 `nvfp4_baked=0` 意味着 **没有任何一个 NVFP4 ConvRot 层被 LoRA bake**。NVFP4 层以 Hadamard 变换（ConvRot）旋转后的权重存储；bake LoRA 需要 "逆旋转 → 应用 LoRA → 再旋转" 的流程。跳过该流程时，原始 LoRA 增量被直接加到已旋转的权重上，权重被破坏，产生噪声。

---

## ② 根本原因

### 因果链（4 步）

1. **purge 剥掉了 HSWQ 的加载包装**
   DisTorch 的 HSWQ purge 调用 `uninstall_zimage_nvfp4_lora_bake()`，剥掉 `ops._load_quantized_module` 上的包装（该包装在 HSWQ 加载量化模块时武装 NVFP4 标志）。此时 `_hswq_nvfp4_full_load` 标记丢失。

2. **`apply_comfy_quant_nvfp4_patches()` 提前返回**
   该函数仅凭 `_PATCHES_APPLIED` 和 `stack_ver` 就判断"已应用"，没有检查 `_load_quantized_module` 的包装是否**实际仍在原位**。因此 purge 之后它仍然提前返回，从未重新应用包装。

3. **重新加载时 NVFP4 标志未被武装**
   没有 `_load_quantized_module` 包装，模型重新加载时 `arm_nvfp4_module()` 不会被调用，各个 Linear 模块上不会设置 `_hswq_nvfp4_convrot` 标志。

4. **bake 函数无法检测 NVFP4，发生错误 bake**
   LoRA bake 时 `_module_is_nvfp4_convrot()` 检查该标志。标志缺失时无法检测 NVFP4 层，于是按 `other_qt`（其他量化）处理；ConvRot 的逆旋转/再旋转被跳过，权重被破坏 → 噪声。

### 更深层背景

- **ComfyUI 会缓存加载器节点的输出（MODEL 对象）。** 即使 purge 把模型从 `current_loaded_models` 中移除，加载器节点本身也不会被重新执行。因此"purge → 下次生成"之间 `load_unet` 不会运行，钩子也从未被重新安装。
- purge 的 `uninstall_zimage_nvfp4_lora_bake()` 会剥掉 `Dynamic.load` 的包装——这是正确的设计（"切换回 SDXL 之前清理 ZI 钩子"）。真正的问题是**剥掉之后没有任何重新武装（re-arm）的机制**。

### 4-1. `nodes/zimage_nvfp4/load_unet.py`（`d97bb5b` 中新增）

紧跟 `_ensure_dynamic_load_bake_wrap()` 之后新增的函数：

```python
def _install_permanent_dynamic_load_guard() -> None:
    """Install an outer ModelPatcherDynamic.load guard the purge cannot peel.

    The purge uninstall_zimage_nvfp4_lora_bake walks the chain of wraps stamped
    ``_hswq_zi_nvfp4_lora_bake`` and restores the unwrapped Dynamic.load. After that,
    nothing re-installs the bake hook because ComfyUI caches the loader-node output
    and never re-runs load_unet. The 2nd generation then runs without the NVFP4
    ConvRot LoRA bake and produces noise.

    This guard is a separate, permanent wrap (NOT stamped ``_hswq_zi_nvfp4_lora_bake``),
    so the purge deep-clean walks past it. On every Dynamic.load it ensures the bake
    hook is installed via ``_ensure_dynamic_load_bake_wrap()`` (a no-op when the hook
    is already armed at the current version).
    """
    try:
        import comfy.model_patcher as mp
    except ImportError:
        return
    Dynamic = getattr(mp, "ModelPatcherDynamic", None)
    if Dynamic is None:
        return
    cur = getattr(Dynamic, "load", None)
    if cur is None or getattr(cur, "_hswq_zi_rearm_guard", False):
        return

    def _guarded_load(self, *args, **kwargs):
        try:
            _ensure_dynamic_load_bake_wrap()
        except Exception:
            pass
        return cur(self, *args, **kwargs)

    _guarded_load._hswq_zi_rearm_guard = True  # type: ignore[attr-defined]
    _guarded_load._hswq_zi_rearm_guard_prev = cur  # type: ignore[attr-defined]
    Dynamic.load = _guarded_load
```

### 4-2. `nodes/zimage_nvfp4/zi_comfy_quant_nvfp4.py`（`fdc60bc` 中修复）

```python
    mp_fn = getattr(ops, "mixed_precision_ops", None)
    stack_ver = _effective_nvfp4_stack_ver(mp_fn)
    # The HSWQ purge peels the ops._load_quantized_module wrap (drops the
    # _hswq_nvfp4_full_load stamp) while leaving _PATCHES_APPLIED and the
    # detect_unet_config stamp intact. If the load wrap is gone, the arming
    # (arm_nvfp4_module -> _hswq_nvfp4_convrot) never fires on reload, so the
    # 2nd generation bakes NVFP4 layers as other_qt -> noise. Only early-return
    # when the load wrap is still armed; otherwise fall through to re-apply.
    _load_wrap_ok = bool(
        getattr(ops._load_quantized_module, "_hswq_nvfp4_full_load", False)
    )
    if (
        _PATCHES_APPLIED
        and _load_wrap_ok
        and getattr(model_detection.detect_unet_config, "_hswq_nvfp4_packed_dims", False)
        and stack_ver >= _NVFP4_STACK_VER
    ):
        return True

    # Already patched detect/load but LoRA bake missing: re-wrap mixed_precision_ops only.
    if _load_wrap_ok and getattr(model_detection.detect_unet_config, "_hswq_nvfp4_packed_dims", False) and stack_ver < _NVFP4_STACK_VER:
        # Z Image: INT8 wrap used to drop _hswq_nvfp4_stack_ver → false "upgrade"
        # that wrapped TC over ConvRot parity → double online rotate after refresh.
        if _mp_chain_has_comfy_only(mp_fn) or (
            _PATCHES_APPLIED
            and stack_ver == 0
            and getattr(mp_fn, "_hswq_int8_conv_patched", False)
        ):
            try:
                if mp_fn is not None:
                    mp_fn._hswq_nvfp4_stack_ver = _NVFP4_STACK_VER  # type: ignore[attr-defined]
            except Exception:
                pass
            _PATCHES_APPLIED = True
            _console(
                "[HSWQ NVFP4] stack ver stamped "
                "(skip TC upgrade; comfy_parity / INT8 chain intact)"
            )
            return True

        _orig_mp = getattr(mp_fn, "_hswq_nvfp4_orig_mp", None)
        if _orig_mp is None:
            _orig_mp = mp_fn

        def mixed_precision_ops_upgraded(*args, **kwargs):
            mp = _orig_mp(*args, **kwargs)
            Lin = mp.Linear
            # Never wrap TC over ConvRot parity (Z Image double-rotate / noise).
            if getattr(Lin.forward, "_hswq_nvfp4_convrot_parity", False):
                attach_nvfp4_linear_lora_bake(Lin)
                return mp
            if not getattr(Lin.forward, "_hswq_nvfp4_full_forward", False):
                Lin.forward = make_nvfp4_linear_forward(Lin.forward)
            attach_nvfp4_linear_lora_bake(Lin)
            return mp

        mixed_precision_ops_upgraded._hswq_nvfp4_full_forward = True  # type: ignore[attr-defined]
        mixed_precision_ops_upgraded._hswq_nvfp4_stack_ver = _NVFP4_STACK_VER  # type: ignore[attr-defined]
        mixed_precision_ops_upgraded._hswq_nvfp4_orig_mp = _orig_mp  # type: ignore[attr-defined]
        ops.mixed_precision_ops = mixed_precision_ops_upgraded
        _PATCHES_APPLIED = True
        _console(
            "[HSWQ NVFP4] upgraded stack ver=%s "
            "(ConvRot Linear LoRA bake: convert_weight unrotate + set_weight re-rotate)"
            % _NVFP4_STACK_VER
        )
        return True
```

## ⑤ 代码含义

### 5-1. `_install_permanent_dynamic_load_guard()`（load_unet.py）

**目的：** 在 `ModelPatcherDynamic.load` 外侧安装一个 purge 无法剥掉的"最后防线"守卫。

- 它带有 `_hswq_zi_rearm_guard` 标记，但**不带 `_hswq_zi_nvfp4_lora_bake` 标记**。purge 的 `_deep_clean_dynamic_load()` 只沿带 `_hswq_zi_nvfp4_lora_bake` 标记的包装逐个剥离，因此该守卫会被跳过、保持原样。
- `_guarded_load` 在每次 `Dynamic.load` 调用时先执行 `_ensure_dynamic_load_bake_wrap()`。该函数是"bake 钩子已武装则为 no-op，被剥掉则重新安装"，所以每次调用几乎零开销。
- 然后调用原始 `cur`（被剥掉后的裸 `Dynamic.load`）。顺序是"守卫 → 重新武装检查 → 实际加载"，因此 **bake 钩子被剥掉的状态下 Dynamic.load 永远不会运行**。
- `_guarded_load._hswq_zi_rearm_guard_prev = cur` 只是保留原始函数，供将来调试使用。

### 5-2. `_load_wrap_ok` 守卫（zi_comfy_quant_nvfp4.py）

**目的：** "补丁已应用"的判断不再只凭标志，而是检查包装是否**实际存活**。

- `_load_wrap_ok = bool(getattr(ops._load_quantized_module, "_hswq_nvfp4_full_load", False))` 检查 `_load_quantized_module` 是否仍是 HSWQ 的包装（带 `_hswq_nvfp4_full_load` 标记）。
- purge 剥掉包装后，`_hswq_nvfp4_full_load` 消失，`_load_wrap_ok` 变为 `False`。
- 第 1 个 `if`（提前返回）增加 `and _load_wrap_ok` 意味着**包装被剥掉时不再提前返回**——执行落入完整重新应用路径（`_orig_detect` 及之后），重新包装 `_load_quantized_module`。
- 第 2 个 `if`（`stack_ver < _NVFP4_STACK_VER` 的重新包装路径）也加了 `_load_wrap_ok`。该路径只重新包装 `mixed_precision_ops` 然后提前返回，不重新包装 `_load_quantized_module`；因此包装被剥掉时也必须跳过该路径，执行完整重新应用。
- 结果：第 2 次加载时 `arm_nvfp4_module()` 再次运行，所有模块重新设置 `_hswq_nvfp4_convrot` → bake 函数正确检测 NVFP4 层 → `nvfp4_baked=86` 恢复。

### 5-3. purge 后的缓存重置（nodes/purge_vram.py）

**目的：** purge 后告诉 ComfyUI "重新执行加载器节点"。

- purge 会从 `current_loaded_models` 移除所有模型，但 **MODEL 对象仍留在 ComfyUI 的加载器节点输出缓存中**。若不处理，下次生成会复用缓存的 MODEL，`load_unet` 不再运行（即 TC 栈永远不会重建）。
- `prompt_queue.set_flag("unload_models", True)` 和 `set_flag("free_memory", True)` 设置标志，告诉 ComfyUI executor "下次提示词前卸载所有模型并丢弃缓存的节点输出"。
- 这使加载器节点在下次生成时重新执行，运行完整链条 `load_unet_nvfp4_weight_dtype()` → `apply_comfy_quant_nvfp4_patches()` → `install_zimage_nvfp4_lora_bake()` → `_install_permanent_dynamic_load_guard()`，完全重新武装 TC (W4A4) 栈。
- `currently_running` 检查防止在提示词处理中途设置标志导致误动作。`except` 吸收服务器未初始化等环境差异。

## 整体图景（三层防御）

| 层 | 文件 | 作用 |
|----|---------|------|
| 1 | `nodes/purge_vram.py` | purge 后重置 ComfyUI 缓存，**保证加载器重新运行** |
| 2 | `zi_comfy_quant_nvfp4.py` | 重新运行的加载器**必定执行完整重新应用**（检测包装被剥） |
| 3 | `load_unet.py` | 此后**每次 Dynamic.load 自动重新武装 bake 钩子** |

第 1 次生成与之前一样正常。有了这 3 层，purge 之后的第 2 次及以后生成也保证执行正确的 NVFP4 ConvRot LoRA bake。
