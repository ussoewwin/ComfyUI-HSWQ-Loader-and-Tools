# Release Notes（中文）：v3.7.6 HSWQ UNet Loader 新增 Flux1 ConvRot W4A8 加载

## 概述

**Flux1 混合包现在通过 HSWQ UNet Loader 以专用的 `Flux1 ConvRot W4A8` 权重类型加载。** 一个 Flux1 混合包在单个文件内同时携带 170 个 `asym_w4a8_int8` 层与 144 个 `int8_tensorwise` 保护层（实测包 `F1D_unlockV3_hswq_r170_hybid_convrot_w4a8.safetensors` 为 8,989,783,965 字节、1,748 个键）。打包后的 4-bit 权重不会被改写：INT8 保护层走 requant 化的 LoRA bake，每个 W4A8 层把 LoRA delta 作为 factorised residual 加在 stock grouped-int8 GEMM 之后。

---

## 特性

- **专用权重类型 + 自动检测**：`weight_dtype` = `Flux1 ConvRot W4A8` 显式选择该路径；`default` 也会通过检测到达，分发顺序为 INT8 → NVFP4 → W4A8，带保护层的混合包不会被 INT8-only 检测抢走。
- **INT8 保护层保留真正的 requant bake**：实测运行报告 `total=144 requant=144 int8_round=0 shape_skip=0` 与 `path OK (all requant)` —— 没有任何层回退到会破坏 delta 的随机 int8 舍入。
- **W4A8 层保持打包权重不变**：bake 把每个 LoRA delta 移入 factorised terms，在 stock grouped-int8 GEMM 之后应用。实测运行报告 `baked 170 W4A8 layers as residuals (skipped non-W4A8 keys=144)` 与 `terms_set=170`。
- **装载顺序与重复装载**：加载器先装载 INT8 栈、再装载 W4A8 栈；重复装载始终只得到一组 INT8+W4A8，不再出现包装嵌套。
- **残差执行有日志**：首次命中、每 500 次、以及结束时的统计以 `EVIDENCE` 行输出（`terms_set` / `residual_layers` / `residual_hits`）；加载行显示 `LoRA bake=pending at patcher load` 而不是 bake 前的 0 值。
- **在真实包上实测**：16 step、EasyCache 跳过 6 step 的运行报告 `residual_layers=170` 与 `residual_hits=1700`（170 层 × 10 个有效 step），无 ERROR、Traceback、BROKEN 行。
- **对 float32 参照的数值核验**：全部 170 个 W4A8 层的已执行残差与 `x @ (Σ delta)^T` 的 cosine 最小 0.999998450（均值 0.999998625、max|diff| 1.206112e-02 —— 即 bf16 输出舍入），且两个 LoRA 在全部 170 层上叠加；144 个 INT8 层的 bake 后权重位移为 delta 范数的 1.0007–1.0338 倍（均值 1.0084），`cos(W1-W0, delta)` 最小 0.9041 / 均值 0.9886。

---

## 兼容性

- **适用范围**：W4A8 权重类型面向由 [Hybrid-Sensitivity-Weighted-Quantization](https://github.com/ussoewwin/Hybrid-Sensitivity-Weighted-Quantization) 量化的 Flux1 混合包；它不是通用的 4-bit 加载器。
- **其余路径不变**：Z Image ConvRot NVFP4、Krea2 / SDXL / SD1.5 ConvRot INT8、FP8 与普通 FP16 加载走与之前相同的代码路径。加载器节点显示为 **HSWQ UNet Loader**（DisTorch2 版本：**HSWQ UNet Loader (DisTorch2)**）。
- **DisTorch2**：W4A8 权重类型尚未在 DisTorch2 加载器下验证；Krea2 ConvRot INT8 仍是其中唯一验证过的 `weight_dtype`。
