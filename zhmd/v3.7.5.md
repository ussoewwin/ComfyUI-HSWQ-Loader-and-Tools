# Release Notes（中文）：v3.7.5 fast-disk guard 改在 ComfyUI 的提前导入检查之后装载

## 概述

**fast-disk guard 改为在 ComfyUI 的提前导入检查之后装载，启动时不再报 `Torch already imported`。** 原先前置启动脚本会在 prestartup 阶段立即安装 fast-disk guard，而安装过程会触达 `comfy.memory_management`，该模块会导入 `torch`。于是 ComfyUI 在 `main.py:262` 执行自身检查之前，`torch` 就已经进入 `sys.modules`，每次启动都会记录 `WARNING: Potential Error in code: Torch already imported, torch should never be imported before this point.`

v3.7.5 改为在 `comfy.memory_management` 完整加载之后的第一次导入时装载 guard。`comfy.memory_management` 首次由 `comfy.utils` 在 `main.py` 内部导入，该处紧随上述检查、且远早于 `comfy_aimdo.control.init_devices`，因此 guard 仍然在 aimdo 初始化之前就位。装载过程是幂等的，重复导入不产生额外代价，guard 自身的条件也未改动。

---

## 特性

- **启动不再出现 `Torch already imported`**：prestartup 完全不再导入 `comfy`。guard 由导入钩子在 `sys.modules` 中已存在 `comfy.memory_management` 且该模块具备 `read_tensor_file_slice_into` 时装载，实际发生在 `import comfy.utils` 内部 —— 即检查之后、`init_devices` 之前。
- **guard 仍在 aimdo 之前就位**：`[HSWQ FastDisk] ... armed` 在 `aimdo_setup_hooks` 与 `comfy-aimdo inited` 之前打印，五个子补丁均报告已应用（`control`、`host_buffer`、`model_vbar`、`vram_buffer`、`mem_slice`）。
- **安装失败仍会被报告**：`_install_fastdisk_support()` 现在返回 bool，调用方在失败时打印 `[HSWQ FastDisk] support install failed: <原因>`。既不吞掉错误，也不遮蔽输出。
- **幂等装载**：`_FASTDISK_INSTALLED` / `_FASTDISK_INSTALLING` 保证安装只执行一次，之后的导入立即返回。
- **其他补丁不受影响**：DiT 量化权重锁与 INT8 ControlNet 追加补丁的行为与之前完全一致。
- **fast-disk 未被禁用也未被替换**：没有追加任何回退路径，使用的仍是原生读取路径。

---

## 兼容性

- **ComfyUI 本体**：已验证在 `main.py:262` 执行该检查、并在 `main.py:296` 调用 `init_devices` 的本体上工作。guard 在 `main.py:266`（`import comfy.utils`）处装载。
- **其他加载器**：若某个加载器在 `comfy.memory_management` 存在之前就导入了 `comfy`，guard 只会在之后第一次满足条件的导入时装载，不会丢失。
- **prestartup 阶段的 GPU 状态**：装载时 `torch.cuda.is_initialized()` 仍为 `False`，且不存在副线程，符合 guard 自身的先决条件。
- **模型加载、ConvRot INT8 pack、任何节点均无行为变化**：本版本只改变 guard 的安装时机。
