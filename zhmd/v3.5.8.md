# v3.5.8 发行说明（中文）

## 概述

在 v3.5.8 中，我们从 `HSWQ ConvRot INT8/ConvRot NVFP4 UNet Loader`（`HSWQFP8E4M3UNetLoader`）节点中**彻底移除了内置的 `attention_accel`（default / sa2）选项及关联的 SageAttention2 注入逻辑**。

注意力加速机制现已与模型加载器完全解耦，推荐通过独立的专用外部补丁节点（如 `Patch Sage Attention` 等）进行模块化控制。这不仅避免了多重 Attention Patch 的潜在冲突，也让 UNet Loader 能够更纯粹、更稳定地专注于模型权重加载、量化格式支持（INT8 / NVFP4 ConvRot）与执行后端调度。

---

## 主要变更与技术细节

### 1. 从 UNet Loader 中彻底移除 `attention_accel`
- **节点定义**：从 `HSWQFP8E4M3UNetLoader.INPUT_TYPES` 中移除了 `attention_accel` 下拉菜单部件。
- **加载器内核清理**：在以下各个后端调度实现中全面清理了 `sa2` 条件注入逻辑：
  - INT8 / ConvRot INT8 分发路径（`patches/comfy_quant_int8.py`）
  - Z Image ConvRot NVFP4 分发路径（`nodes/zimage_nvfp4/load_unet.py`）
  - Krea2 ConvRot NVFP4 分发路径（`nodes/krea2_convrot_nvfp4/load_unet.py`）
  - DisTorch2 加载包装器（`nodes/hswq_unet_distorch2.py`）

### 2. 严格保持向后兼容性
- **工作流无损运行**：`load_unet` 及底层的分发函数严格保留了 `**kwargs` 关键字参数吸收机制。
- 即使加载之前保存的、带有 `attention_accel` 参数的历史工作流 JSON，也能平滑忽略该旧参数并正常执行，绝不会引发 `unexpected keyword argument` 崩溃。
