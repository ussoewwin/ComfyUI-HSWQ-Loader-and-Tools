## 摘要

**v3.3.1** 为 **HSWQ ConvRot INT8/ConvRot NVFP4 UNet Loader** 增加 **Z Image / ZIT ConvRot NVFP4** 支持。

Z Image 的 HSWQ ConvRot NVFP4 UNet 包走 `nodes/zimage_nvfp4` 专用栈，遵循 `hswq/benchmark` 的 **Comfy parity** 约定：stock MixedPrecision GEMM（`F.linear` / `aten.addmm`）+ 对离线旋转 ConvRot 权重的 **在线 act rotate**。**不使用** SDXL Checkpoint Loader 的 Tensor Core 产品前向（`_hswq_nvfp4_full_forward` / `scaled_mm_nvfp4`）。

典型包为混合结构：约 **120** 层 NVFP4 ConvRot Linear + 约 **60** 层 INT8 protect Linear，两侧均加载。Dynamic VRAM（`ModelPatcherDynamic` / MultiGPU）下的 LoRA bake 经 bake hook **v4** 修复，加载后 `patches_left=0`。

**仅支持经 [Hybrid-Sensitivity-Weighted-Quantization](https://github.com/ussoewwin/Hybrid-Sensitivity-Weighted-Quantization) 量化的模型。** 第三方 ConvRot NVFP4 UNet 包不在支持范围内。

## 新增

### UNet 加载入口

- 加载器标题：**HSWQ ConvRot INT8/ConvRot NVFP4 UNet Loader**
- `weight_dtype` = **`ConvRot NVFP4`**，或 safetensors 呈现 comfy_quant / HSWQ `nvfp4` 特征时使用 **`default`**
- NVFP4 UNet 分发安装在 INT8 **之后**，避免混合包被 INT8 专用自动检测抢走
- 显存清理：工作流末尾使用 [ComfyUI-DistorchMemoryManager](https://github.com/ussoewwin/ComfyUI-DistorchMemoryManager) 的 **General Purge VRAM V2**，并打开 **`HSWQ`**（与 SDXL HSWQ INT8 / NVFP4 同因）

### 包 `nodes/zimage_nvfp4/`

| 模块 | 作用 |
|------|------|
| `load_unet.py` | UNet 加载 / dtype 分发 / 强制最外层 Dynamic bake wrap |
| `nvfp4_comfy_parity.py` | 以 stock GEMM + 在线 act rotate 替换 TC Linear.forward；武装 NVFP4 与 INT8 protect ConvRot |
| `nvfp4_lora_bake.py` | Dynamic VRAM LoRA bake（v4）：最外层 `ModelPatcherDynamic.load` + `load_models_gpu` hook |
| `nvfp4_addmm_patch.py` | 为 `TensorCoreNVFP4Layout` 注册 `aten.addmm`（填补 kitchen 缺口，避免静默双侧 dequant） |
| `nvfp4_tc_gate.py` | GPU CC / CUBLAS 门控；scaled_mm 不支持时压制 TC WARNING |
| `require_parity.py` | 失败即停：确认 Z Image 上未残留 TC full-forward |
| `__init__.py` | 包导出 |

### `prestartup_script.py`

- 在自定义节点 `__init__.py` 之前运行
- **不得**把本扩展包根目录加入 `sys.path`（会遮蔽 ComfyUI `nodes`，导致 `AttributeError: module 'nodes' has no attribute 'init_extra_nodes'`）
- 将 UNet NVFP4 weight-dtype 加载无绑定到 `nodes.zimage_nvfp4.load_unet`（无递归）

## 更改

### 与 SDXL NVFP4 隔离

- SDXL Checkpoint Loader 继续使用 / 恢复 `nodes/nvfp4` 下的 **Tensor Core 产品**栈
- Z Image 在共享 NVFP4 补丁**之后**应用 **comfy_parity**，且不得留下已武装的 TC forward
- Z Image ConvRot NVFP4 逻辑位于 `nodes/zimage_nvfp4` —— 本版本**不会**把 SDXL TC 产品路径改成 Z Image 默认

### INT8 Dynamic bake 不得把 NVFP4 当 INT8

- `patches/comfy_quant_int8.py`：`_qt_is_int8_tensorwise` 要求 layout 名包含 `TensorWiseINT8`
- 此前裸 `isinstance(weight, QuantizedTensor)` 会把**任意** QT（含 NVFP4）当成 INT8，可能对 ConvRot NVFP4 层武装 INT8 Dynamic bake
- Dynamic INT8 bake 版本升至 **6**

### Dynamic VRAM LoRA bake（关键路径）

**v4 前症状：** `Dynamic.load` ENTER 可能显示 `patches=180` 且 `nvfp4_convrot=False`，随后跳过 bake —— LoRA 看似无效，`LowVramPatch` 仍挂着。

**根因：** kitchen `QuantizedTensor` 继承 `torch.Tensor.layout`（`torch.strided`）。优先读 `qt.layout` 时 `type(layout).__name__` 字面为 `"layout"`，导致 `_qt_is_nvfp4` 恒为 False。更早的 hook 还要求 `module.weight` 上有 QT，而 Dynamic VRAM 常把 QT 藏在 `get_key_weight` 后面。

**Bake hook v4（`b8d1144`）：**

- 优先 `_layout_cls` / `layout_cls`，不要用 `Tensor.layout`
- 以模块标志 `_hswq_nvfp4_convrot` 门控 bake（不要求 `module.weight` 上有 QT）
- ENTER 日志：`flagged=` / `qt_on_weight=`
- NVFP4 ConvRot bake 之后：剩余 INT8 / 其他 QT bake，直到 `patches_left=0`
- 最外层包裹 `ModelPatcherDynamic.load` + `load_models_gpu` bake hook；若被 INT8 / MultiGPU 覆盖则重新武装
- bake 后**不要**删除 `module._v`（与 INT8 Dynamic bake 相同的 VBAR 纪律）

**成功控制台契约（示例）：**

```text
Dynamic.load bake hook ON v4
ENTER #1: patches=180 nvfp4_convrot=True flagged=120 qt_on_weight=120
Dynamic.load bake #1: nvfp4_baked=120 int8_baked=60 ... skip_not_convrot=60 patches_left=0
[HSWQ LoRA Bake] total=180 requant=180 ... path OK (all requant)
```

INT8 protect 键上的 `skip_not_convrot` 采样是预期现象：这些键走剩余 INT8/QT bake 路径，而非 NVFP4 ConvRot 路径。

### Comfy parity 前向（画质）

- 离线 ConvRot 权重（`W` 已离线旋转）在 stock Linear 前需要 **在线 act rotate**
- 清除权重上 kitchen `Params.convrot`，避免 kitchen **再次**旋转（双重旋转）
- 在 Z Image 上使用产品 TC full-forward 会使 Pixel SSIM 相对 bench parity 路径崩坏；Z Image 固定走 parity

## 操作说明

1. 将本自定义节点更新 / 重新安装到标签 **v3.3.1**（或 `e81ddbe` 及之后的 `main`）。
2. **完全重启** ComfyUI。
3. 将 HSWQ ConvRot NVFP4 UNet 放到 `diffusion_models`。
4. 在 **HSWQ ConvRot INT8/ConvRot NVFP4 UNet Loader** 上将 `weight_dtype` 设为 **`ConvRot NVFP4`**（或带 NVFP4 标记的 `default`）。
5. 按需连接 LoRA / MultiGPU Dynamic VRAM / sampler。
6. 确认控制台出现 bake hook **v4**、`nvfp4_convrot=True`、`patches_left=0`。
7. 使用 HSWQ NVFP4 / INT8 时，工作流末尾加 **General Purge VRAM V2**（打开 `HSWQ`）。
8. **不要**期望本 UNet 加载器走 SDXL Checkpoint Loader 的 Tensor Core 产品路径。

## 兼容性

| 项目 | 策略 |
|------|------|
| 量化器 | **仅** [Hybrid-Sensitivity-Weighted-Quantization](https://github.com/ussoewwin/Hybrid-Sensitivity-Weighted-Quantization) |
| Z Image INT8（旧 HSWQ 专用线） | 已结束发布；优先原生 ConvRot INT8 或本 NVFP4 路径 |
| SDXL ConvRot NVFP4 | 仍由 **HSWQ Checkpoint Loader (SDXL)** + `nodes/nvfp4` TC 产品路径负责 |
| ComfyUI-master | 本扩展不修改 |
