# v3.6.4 发布说明（中文）

## 概述

**SDXL ConvRot INT8 运行栈正式集成整去噪器（Whole-denoiser）CUDA Graph Replay 机制**，实现稳定推理速度提升 **+22.1%（3.27-3.28 → 3.35-3.36 it/s）**，端到端生成耗时缩短 **+17.5%（1024x1024 下平均单图 9.23s → 7.62s，含捕获开销）**，且输出潜空间轨迹与急切执行保持**位完全一致（Bit-equal，maxdiff 0.0，25 个随机种子分叉数 0/25）**。

此前，SD1.5 INT8 运行栈已证明消除 CPU Kernel Launch 开销能带来显著性能跃升（512 分辨率下 +14%）。在 SDXL 上，尽管此前的池化激活旋转（Pooled activation rotate）已成功解决 FP32 精度提升瓶颈（单步旋转耗时从 257.3 ms 骤降至 52.5 ms），但前向传播仍部分受限于 CPU 调度发射延迟。整去噪器 CUDA Graph Replay 消除了数百个 Kernel 的 CPU 启动开销，在首次执行时完成图捕获，随后所有迭代步骤直接在 GPU 端回放执行。

该架构实装于 SDXL 专用模块（`nodes/sdxl_convrot_int8/sdxl_convrot_fast.py`），并在 `patches/comfy_quant_int8.py` 的 Checkpoint 与 UNet 双加载分支中统一采用“图优先、自动退火回退”的设计。

## 技术架构与实装细节

### 1. SDXL 专用图执行器（`_Sd15CudaGraphExecutor`）
实装于 `nodes/sdxl_convrot_int8/sdxl_convrot_fast.py`（第 359-500 行）：
- **特征签名索引**：图缓存以 `(x, t, context)` 输入特征为键（张量形状、dtype、设备排他排序）。当遇到分辨率或上下文形状改变时，自动触发新图捕获。
- **缓冲区隔离**：每次回放调用前从静态 Copy-in 缓冲区传入输入；输出严格通过 `sy.clone()` 返回急切等效张量，杜绝输出内存与内部 CUDA 图内存池发生别名引用。
- **稳定捕获机制**：采用 `capture_error_mode="relaxed"`，在独立侧流（Side-stream）上执行 3 次 Warmup 预热，捕获前后执行硬件级流同步。
- **潜空间尺寸限制**：设置 `_MAX_CAPTURE_LATENT_SIDE = 128`（完全覆盖至 1024x1024 分辨率）。超大尺寸自动绕过图捕获进入急切路径。
- **软失败回退**：若捕获异常，仅记录告警并安全降级至急切模式，不破坏该模型实例的图基础设施。

### 2. 池化激活旋转中的捕获防污染守卫（`_capture_active()`）
研发实测中排查并解决了一个严重的隐式数值故障：
- **故障根因**：池化激活旋转在层间复用按形状预分配的共享缓冲区。在 CUDA Graph 捕获与 Warmup 期间，由于多个节点在静态流中同时重用这些共享缓冲区，导致中间激活张量发生内存覆写与状态污染，引发灾难性轨迹漂移（实测 3 种配置下最大误差 maxdiff 分别高达 2.31 / 3.41 / 4.02）。
- **防御机制**：执行器在 Warmup 预热、图捕获以及回放 Copy-in 窗口期间，全局置位 `_STATE["in_graph_capture"] = True`。
- **守卫执行**：`_pooled_rotate` 与 `_pooled_helper_rotate` 主动探测 `_capture_active()`。一旦处于捕获窗口内，立即强制切换为**普通非池化激活旋转**。录制生成的 CUDA Graph 因而全部由原生的无别名 Kernel 构成，彻底消除了共享内存污染，重放数值达到**完全位一致（实测 maxdiff 0.0）**。
- 捕获窗口外的普通未捕获急切步骤仍继续享有池化缓冲区的速度优势。

### 3. 加载分支中的“图优先”梯队架构
`patches/comfy_quant_int8.py` 中的 Checkpoint 与 UNet 两条加载分支均实装图优先梯队：
```python
if is_convrot and needs_conv2d and _model_is_sdxl_unet(model):
    _arm_sdxl_cudagraph(model)  # 尝试图装备
    # 成功：启用图优先执行
    # 失败：记录日志并退火至池化旋转急切路径（保持此前稳定速度）
```
两套路径在单模型状态下互斥，杜绝了共享状态下的脏缓冲区风险。

### 4. 框架兼容性与 Fail-Closed 审计扩展
- **ComfyUI v2.14 / inner.adm_channels 适配**：ComfyUI v2.14 将 `adm_in_channels` 属性从 `UNetModel` 移除。加载器装备守卫适配为同时检测 `dm.adm_in_channels` 或 `inner.adm_channels`（SDXL 下为 2816），解决了 CUDA 13.2 环境下加载器拒绝装备的问题。
- **Fail-Closed AST 旋转调用审计**：ComfyUI v2.14 新增了 `backends/ascend/__init__.py` 旋转调用点。由于本扩展对所有未经审查的旋转调用采用严格的 Fail-closed 拦截，在确认其满足安全重绑定规范后，已将其正式登记至 `_AUDITED_ROTATE_FILES`。

## 捕获阻碍排查与实测修复矩阵

系统性排查并修复了三种在运行时触发 CUDA Graph 捕获中断的边界情况：

| 故障现象 / 报错 | 根因定位 | 实装解决方案 |
|---|---|---|
| `Cannot copy between CPU and CUDA tensors during CUDA graph capture unless the CPU tensor is pinned` | ComfyUI ModelPatcher 加载后，CUDA 13.2 下 `model_sampling.timestep()` 读取的 `log_sigmas` 仍驻留在 CPU 上。 | 执行器在侧流 Warmup 之前，对 `model_sampling` 缓冲区执行单次设备迁移至目标 GPU。 |
| `dependency created on uncaptured work in another stream` (`cudaErrorStreamCaptureIsolation`) | ComfyUI 异步权重 Offload 机制在步间触发了跨流事件同步。 | 确保权重完全驻留 GPU 设备（`full_load=True`）。捕获遇到跨流依赖时优雅降级至急切模式。 |
| 池化旋转下重放数值严重漂移（maxdiff 2.31–4.02） | 图流录制期间多个连续层复用了共享的中间输出缓冲区。 | 实装 `_capture_active()` 守卫，在捕获窗口强制采用独立非池化旋转（§2）。 |

由于 `model_sampling.timestep()` 缓冲区仅单次迁移至设备，急切路径前向读取相同已注册缓冲区，急切模式数值同样严格保持完全一致。

## 架构边界与模块隔离

- **严格的家族隔离**：所有 SDXL CUDA Graph 重放代码严格限定在 `nodes/sdxl_convrot_int8/sdxl_convrot_fast.py` 与 `patches/comfy_quant_int8.py` 的受守卫分支内。
- **无任何侵入**：SD1.5、Z Image、Krea2、FLUX、Qwen、SAM3 加载路径均未引入任何相关代码（0 字节改动）。
- **两阶段验证**：代码首先在独立的 Benchmark 测试栈完成验证（Stage 1 门禁：位完全一致重放 + 1024 分辨率下 +22.1% 提速），验证通过后才正式接入生产加载器（Stage 2）。

## 运维排查指南

在加载任意 SDXL ConvRot INT8 模型包（`int8_tensorwise` 或反向混合包）时：
1. **正常就绪**：控制台将打印 `[HSWQ INT8][SDXL graph] armed`，首个去噪步打印 `captured #1`。后续所有迭代将以 3.35+ it/s 全速回放。
2. **装备回退告警**：若出现 `arm failed ... fallback to pooled-rotate eager path`，系统安全回退至图机制实装前的稳定基线（3.27–3.28 it/s）。
3. **捕获跳过**：若遇到罕见或动态变化的张量特征，捕获跳过后该特征自动转为急切模式执行，画质与数值稳定性不受任何影响。
