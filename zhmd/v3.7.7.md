# Release Notes（中文）：v3.7.7 修复 DisTorch2 在 ComfyUI v0.46.0 上的加载崩溃

## 概述

**DisTorch2 在 ComfyUI v0.46.0 上恢复正常加载。** ComfyUI v0.46.0 从 `comfy.model_management` 中删除了 `lowvram_available` 模块全局变量（directml 移除，上游提交 `c5751c81ab`），而 DisTorch2 的加载路径直接 import 了这个名字 —— 因此每次 DisTorch2 加载都在模型载入之前抛出 `ImportError: cannot import name 'lowvram_available' from 'comfy.model_management'`。

修复方式是 `distorch/distorch_2.py` 里的一个小兼容助手：补丁后的 `load_models_gpu` 改为通过 `_hswq_lowvram_available()` 读取该标志，而不是直接 import。全局变量存在时（ComfyUI <= 0.45.x）返回其原值，旧行为保持不变；不存在时（v0.46.0+）返回 `True` —— 这正是 v0.46.0 自身改写后的条件 `(vram_set_state == LOW_VRAM or NORMAL_VRAM) and not force_full_load` 的语义：上游删除该变量时，唯一会把它置为 `False` 的情况（directml）也随之消失，低显存路径从此始终可用。

---

## 特性

- **两条 ComfyUI 版本线都能工作**：同一个文件在 ComfyUI <= 0.45.x（照旧读取全局变量）与 v0.46.0+（采用新的「始终可用」语义）上都能加载，不做版本探测。
- **改动最小**：仅触碰 `distorch/distorch_2.py` —— 一个模块级助手、import 行、以及引用该全局变量的那一个 `if`（+13 / -2 行）。DisTorch2 的其余显存逻辑、装载顺序、放置行为均未修改。
- **无新依赖**：助手在调用时才惰性读取 `comfy.model_management`，导入顺序与启动行为不变。

---

## 兼容性

- **范围**：本修复只涉及 DisTorch2 加载路径（`HSWQ UNet Loader (DisTorch2)` 与 DisTorch2 显存管理模块）。其他 HSWQ 路径 —— INT8 / NVFP4 / W4A8 / FP8 / FP16 加载器、提示词增强节点、以及全部补丁 —— 均未触碰。
- **实测**：已在运行中的 ComfyUI v0.46.0 上验证（`comfy.model_management` 无 `lowvram_available` 属性、助手返回 `True`），模块在两条版本线上均可编译并正常导入。
