# v3.6.2 发布说明（中文）

## 概述

**彻底移除 Tensor Boost（Blackwell CUDA Graph）功能与底层运行时代码。**

继 v3.6.1 正式终止 SDXL ConvRot NVFP4 开发后，此前专为 SDXL NVFP4 在 Blackwell（RTX 5090 / sm_120）架构下打造的 CUDA Graph 加速机制（Tensor Boost）已无继续保留的架构基础。本次更新完成了全方位的彻底解耦与清理：移除了节点 UI 中的 `tensor_boost` 部件、清除了中英文文档中的相关说明，并彻底删除了 `nodes/sdxl_convrot_nvfp4/` 底层 523 行 CUDA Graph 捕获与重放基础设施代码。

历史 SDXL NVFP4 模型的推理执行现在 100% 走稳定、确定性的 Eager Pooled 量化与 cuBLAS GEMM 执行路径（`quantize_nvfp4_act_pooled` + `scaled_mm_nvfp4_pooled`），彻底杜绝显存图 Arena 静态膨胀与 CUDA Graph 在动态分辨率下的异常隐患。

---

## 技术背景：Tensor Boost 的生命周期与移除原因

### 1. 为什么最初引入 Tensor Boost？
在最初开发 SDXL ConvRot NVFP4 时，由于 4-bit 量化小 $M$ 维度 GEMM 在 Ada 与 Blackwell 架构上存在微观内核发射开销（Launch Overhead），因此设计了实验性的 CUDA Graph 捕获与重放加速层：
- **形状共享图缓存 (`nvfp4_quant_mm_cudagraph`)**：按输入张量形状聚类，重放时将权重张量与 scale 拷贝至静态显存缓冲区。
- **逐权重图缓存 (`nvfp4_quant_mm_cudagraph_perweight`)**：利用 Blackwell 架构上模型权重地址常驻的特性，直接将权重张量作为图输入，跳过大张量显存拷贝开销。

### 2. 为什么现在彻底移除 Tensor Boost？
1. **SDXL NVFP4 开发终止（v3.6.1）**：
   上游确定性潜空间轨迹测试（Deterministic Latent-Trajectory Gate）已严格证明，4-bit 精度（NVFP4）在 SDXL 庞大的 UNet 注意力结构下无法保持潜空间轨迹一致性（轨迹余弦均值未达 0.90，且被传统 SSIM 的 VAE 解码非线性平滑所掩盖）。SDXL 正式转为全面专注于 **ConvRot INT8（reverse hybrid）**。
2. **ConvRot INT8 完全不使用 Tensor Boost**：
   SDXL ConvRot INT8 依赖原生高性能的 `sdxl_convrot_fast.py` 激活池化路径与原生 INT8 内核，NVFP4 CUDA Graph 机制对其没有任何用处。
3. **消除显存碎片与运行时复杂性**：
   CUDA Graph 机制需要预先分配专属的 CUDA 图内存池（Arena）并常驻静态输入输出缓冲区。在 ComfyUI 复杂的实际生成环境（如不同的图片宽高比、Ultimate SD Upscale 瓦片切块等动态分辨率）中，图缓存不仅占用额外显存，还容易引发 OOM 或重放冲突。彻底移除该机制使显存分配 100% 可预期、轻量且稳定。

## 变更与移除内容详情

### 1. 节点 UI 与执行接口 (`nodes/`)
- **`HSWQ Sampler` (`nodes/hswq_sampler.py`)**：
  - 从 `INPUT_TYPES["required"]` 中彻底移除了 `tensor_boost` 布尔开关部件。
  - 从 `sample()` 执行函数签名与分发逻辑中移除了 `tensor_boost` 参数。
- **`HSWQ Ultimate SD Upscale` (`nodes/nunchaku_usdu.py`)**：
  - 从 `INPUT_TYPES["required"]` 中彻底移除了 `tensor_boost` 布尔开关部件。
  - 从 `upscale()` 执行函数签名与分发逻辑中移除了 `tensor_boost` 参数。
- **向下兼容性**：
  - 既有工作流中已保存的 `tensor_boost` 序列化部件值在加载时会被安全忽略，不会触发任何报错，保证所有历史工作流平滑执行。

### 2. 文档与配置说明 (`README.md`, `zhmd/README.md`)
- 清理了中英文 README 中所有关于 Tensor Boost、CUDA Graph 加速机制、性能对照表以及 RTX 5090 开启建议的段落。
- 移除了环境变量 `HSWQ_NVFP4_TENSORBOOST` 与 `HSWQ_NVFP4_CUDAGRAPH` 的配置说明。

### 3. 底层运行时引擎 (`nodes/sdxl_convrot_nvfp4/`)
- **`nvfp4_conf.py`**：
  - 彻底删除了 `is_nvfp4_cudagraph_enabled()` 函数及相关环境变量解析逻辑。
- **`comfy_quant_nvfp4.py`**：
  - 移除了 `load_checkpoint_sdxl_nvfp4_weight_dtype()` 中对 CUDA Graph 开启状态的检查与 `[HSWQ NVFP4 Tensor Boost]` 控制台提示日志。
- **`nvfp4_forward.py`**：
  - 删除了 `_BLACKWELL_GRAPH_HITS` 计数器与图命中统计字段。
  - 彻底移除了 `_tc_forward_pooled()` 中分发至 CUDA Graph 的分支逻辑。所有 SDXL NVFP4 推理直接通过 Eager 激活池化（`quantize_nvfp4_act_pooled`）与池化矩阵乘法（`scaled_mm_nvfp4_pooled`）完成。
- **`nvfp4_runtime.py`**：
  - 删除了 391 行图基础设施代码，包括 `_GRAPH_CACHE`、`_PER_WEIGHT_GRAPH_CACHE`、`_run_quant_mm`、`nvfp4_quant_mm_cudagraph`、`nvfp4_quant_mm_cudagraph_perweight` 及静态拷贝工具 `_copy_f32_1`。
  - 保留了 `clear_nvfp4_cudagraphs()` 作为安全的空操作函数（no-op），以防止历史残留调用发生导入错误。
