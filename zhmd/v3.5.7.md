# v3.5.7 发行说明（中文）

## 修复

### 1. ComfyUI v0.38 fast-disk 原生读取损坏 / 进程 abort（最重要）

ComfyUI v0.38 把 comfy-aimdo 的存储读取迁移到专用 fast-disk 路径。从不同线程调用原生读取会触发 CUDA 错误、`std::abort()` 或静默读取失败——生成中断，或权重在被破坏的状态下被读入。

**根本原因**: CUDA 原生调用强依赖线程/流上下文。v0.36 及之前全部在调用方线程内完成；v0.38 引入了 fast-disk 专用读取线程，HSWQ 侧路径一旦从别的线程触碰原生函数，上下文即被破坏。

**修复（结构性，非零散修补）**: 新建 `patches/comfy_aimdo_fastdisk_guard.py`（298 行）——

- 把全部原生 aimdo 入口（control / host_buffer / model_vbar / vram_buffer / mem_slice）收敛到单一 `_NATIVE_LOCK` 直列化路径（`_wrap()`）；
- `read_file_to_device_serialised`（file→VRAM 主读取）在失败时 `cleanup_file_reader()` 复位读取槽并重试一次，读取后 `_device_sync()` 等待异步副本完成再放行；
- capture（torch.cuda.graph）期间跳过 device sync，避免把捕获打坏；
- `prestartup_script.py` 的 `_install_fastdisk_support()` 在 ComfyUI `init_devices` 之前安装——CUDA 上下文所有权必须先于一切建立，安装顺序本身是修复的一部分。

结果：ComfyUI 本体零改动，fast-disk 保持启用，恢复 v0.36 级稳定性。

### 2. 连续 prompt「交替出坏图」竞态（2026-10-07 实害）

同一 ComfyUI 进程内连续跑 prompt 时，正常图与畸形图交替出现。16:24 会话 A/B 实测确认 DisTorch purge（DisTorchPurgeVRAMV2 Method 2d）节点的 ON/OFF 就是开关。

**根本原因**: DisTorch purge 为 SDXL 交接剥离 HSWQ 的叠层（包装链），但模块级应用闸门（`_PATCHES_APPLIED` / `_PARITY_APPLIED` / `_GPU_BAKE_INSTALLED` / `_APPLIED`）保持 `True`。下一个 prompt 在同进程内重新加载 Z Image ConvRot NVFP4 / Qwen + ControlNet ConvRot INT8 / Krea2 / SDXL 时，闸门被误认为「已应用」，在半剥离状态下直接采样。

**修复**: 新建 `patches/hswq_purge_rearm.py`（283 行），公开 `hswq_purge_rearm_state()`——

- 按家族**完全分离**的独立判定（绝不混判）：ZI = `_hswq_nvfp4_full_load` 且非 product_tc/krea2；SDXL product = 仅 `_hswq_nvfp4_product_tc`；Krea2 = krea2 专用戳记（含 `detect_unet_config` 的 txtlayers 修正标记）；INT8 = `_hswq_int8_decode_patched` / `_hswq_int8_protect_in_load` / `_hswq_int8_protect_arm_v2` 任一；
- `_walk_layers()` 沿显式反向指针与已知闭包槽（`_orig_load` 等 8 种）做 cycle-safe 全层走查，检查**仍存活包装链上的真实戳记**；
- 只把家族层确实缺失的闸门 `RESET` 为 `False`（下一个加载走正规安装路径重贴）；层还在的家族 `no-op`，从不无差别全清；
- DisTorchPurgeVRAMV2（HSWQ 开关）在 Method 2d 剥离完成后调用本 API。

结果：无需 cleaner 节点，同进程多 prompt·多模型运行稳定。

### 3. Lumina2 在 Blackwell（sm_120）上进程异常终止

`comfy_kitchen` 的 CUDA fused RMS-RoPE 没有 sm_120 内核，dispatch 直飞 fused 内核后 `std::abort()` / missing kernel image 把整个进程打掉。

**修复**: `patches/comfy_quant_int8.py` 新增 `_patch_comfy_kitchen_rms_rope_fallback()`——在 CC≥10 上把 8 个 rms_rope 系 op 从 cuda 后端 capabilities 中移除，注册 `_safe_rms_rope` / `_safe_rms_rope1` / `_safe_ja_forward` 的 eager 安全实现；非 Blackwell 零改动。两个 loader（ModelPatchLoader / ControlNet loader）在加载时确保应用。

## 新增

### 4. DiT 量化权重锁改为运行时补丁

INT8/NVFP4 的「量化权重保持量化」守卫从 `comfy/ops.py` 手改（每次更新必丢）迁移到新建 `patches/comfy_dit_quant_lock.py`（224 行）：以 stock v0.38.x 源文为锚点、断言唯一出现后替换（`cast_bias_weight` / `resolve_cast_module_with_vbar`），staging 全收集后 all-or-nothing 应用；prestartup 的 import 钩子＋脚本末尾安全网双保险。ComfyUI 更新后不再需要重贴核心改动。
