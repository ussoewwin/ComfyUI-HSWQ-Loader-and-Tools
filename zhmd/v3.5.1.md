## 1. 概述

**v3.5.1** 为 **HSWQ ConvRot INT8/ConvRot NVFP4 UNet Loader** 新增 **SageAttention2（SA2）加速**，通过新的 **`attention_accel`** 选项（`default` / `sa2`）启用。

SA2 会把已加载模型的 attention 内核替换为 SageAttention2（INT8 QK `per_warp` + FP8 PV，sm120 自动路径）。它是**可选项** —— `default` 与既往版本完全一致 —— 并且是**按模型启用**的，因此同一图中的其他模型（例如 FP16 基准）不会受到影响。

RTX 5060 Ti 实测：attention 内核约快 **2.3x**，端到端采样在 Z Image ConvRot INT8 上 **-11.4%**、在 Z Image ConvRot NVFP4 上 **-15.4%**，两次 20 种子运行的 bifurcated 均为 **0/20**。

---

## 2. 新增：`attention_accel` 选项（`default` / `sa2`）

**HSWQ ConvRot INT8/ConvRot NVFP4 UNet Loader** 在 `unet_name` 与 `weight_dtype` 之后新增第三个控件：

| 取值 | 行为 |
|:---|:---|
| **`default`** | ComfyUI 原生 attention。**不安装任何补丁** —— 与既往版本完全一致。 |
| **`sa2`** | **SageAttention2**（`sageattn`，INT8 QK `per_warp` + FP8 PV，sm120 自动路径）。仅替换量化模型的 attention；FP16 基准保持原生 attention。 |

实现位于 `hswq/hswq_sa2_accel.py`（新增）。attention 覆写**仅在该 MODEL 的 `forward` 执行期间生效**，因此同时持有两个模型（例如 FP16 参考模型与量化模型）的工作流中，参考模型仍使用原生 attention。

---

## 3. 支持模型 —— 4 种模式，分别独立分发

| `weight_dtype` + 检查点 | 架构 | 被补丁的 attention 模块 |
|:---|:---|:---|
| **Z Image ConvRot INT8** | NextDiT（`comfy.ldm.lumina`） | `comfy.ldm.lumina.model` |
| **Z Image ConvRot NVFP4** | NextDiT（`comfy.ldm.lumina`） | `comfy.ldm.lumina.model` |
| **Krea2 ConvRot INT8** | SingleStreamDiT（`comfy.ldm.krea2`） | `comfy.ldm.krea2.model` |
| **Krea2 ConvRot NVFP4** | SingleStreamDiT（`comfy.ldm.krea2`） | `comfy.ldm.krea2.model` |

每种模式都有**专用的 arm 函数**（`_arm_zimage_int8` / `_arm_zimage_nvfp4` / `_arm_krea2_int8` / `_arm_krea2_nvfp4`）；不存在与其他模式共用代码路径的情况。

### 3.1 三重闸门 —— 不一致时拒绝，绝不混用

1. **由检查点判定**：模式由检查点本身决定 —— comfy_quant `int8_tensorwise` / `nvfp4` 扫描（同时带有 INT8 层的混合 NVFP4 包，按其 `nvfp4` 层归类）加上 Krea2 的 `txtfusion.projector.weight` 标记。
2. **与所选的 `weight_dtype` 交叉校验**：例如对照 Z Image 检查点选择 `Krea2 ConvRot NVFP4` 时，会**拒绝安装 SA2**并记录警告。
3. **加载后再次校验模型类**：模式必须与 `NextDiT`（Z Image）或 `SingleStreamDiT`（Krea2）一致，否则不安装 SA2。

### 3.2 回退与覆盖率报告

- **SDPA 回退**：mask 与 `head_dim > 256`（Krea2 `txtfusion`、Qwen3-VL 文本编码器）；内核异常按每次调用回退。
- **控制台覆盖率行**，确保不完整的运行不会被误认为干净结果：
  `[HSWQ SA2] attention calls: total=... sa2=... fallback(mask)=... fallback(dim)=... errors=...`

## 4. `attention_accel` 的分发链透传

UNet 加载器的 `load_unet` 被三层分发（INT8、Krea2 NVFP4、Z Image NVFP4）包裹。v3.5.1 让它们全部**透传未知的加载器选项（`**kwargs`）**，并在**全部四条真实加载路径**（stock-equivalent INT8、MixedPrecision INT8、Z Image NVFP4、Krea2 NVFP4）中安装 SA2。

本次同时修复了由此暴露的两个缺陷：

- **INT8 分发抢占混合 NVFP4 检查点**：混合包同时带有 INT8 标记，因此选择 `Z Image ConvRot NVFP4` 时可能被 INT8 自动检测路径拦截。现在显式 NVFP4 dtype 会直接透传给 NVFP4 分发。
- **NVFP4 加载路径的 `logging` `UnboundLocalError`**：函数内的 `import logging` 遮蔽了模块级导入。现在统一使用模块级 logger。

---

## 5. 不支持

- **SDXL**（`HSWQ Checkpoint Loader (SDXL)`）**没有** `attention_accel` 选项，也**没有** SA2 代码路径。SA2 仅适用于 **Z Image / Krea2**。
- **不要**将 `attention_accel=sa2` 与 `Patch Sage Attention DM`（ComfyUI-DistorchMemoryManager）叠加 —— 两者都会补丁 attention。使用本加载器的 SA2 时请旁路该节点。
- **依赖** `sageattention` 包。它**仅**在选择 `sa2` 时导入，因此 `default` 不依赖它。

---

## 6. 验证

- **attention 内核（单体）**：随机 q/k/v（fp16、HND、head_dim 128）上 SA2 对 SDPA 的余弦 **0.999258**。
- **Z Image ConvRot INT8，20 个正規种子 x 12 步（1024x1024，cfg 2.5）**：
  - INT8 分支 **18.05 s -> 16.00 s 每种子（-11.4%，1.128x，20/20 种子全部更快）**
  - `final-cosine` 均值 **0.99122 -> 0.99043**，两次运行均 **0/20 bifurcated**
  - SA2 覆盖率 **16320/16320 次调用（100%）**，error 0
- **Z Image ConvRot NVFP4（同进程 A/B，seed 42，TC W4A4）**：**13.68 s -> 11.57 s（-15.4%）**；attention 单体 **189.7 ms -> 82.7 ms（2.29x）**；GEMM 保持 TC（W4A4），`dequant_fallbacks` 0。
- **Z Image ConvRot NVFP4，20 个正規种子**：`final-cosine` 均值 **0.96849 -> 0.97468**，**0/20 bifurcated**。
- **Krea2 ConvRot INT8（5 种子、12 步）**：INT8 分支约 **19.2 s -> 17.7 s 每种子（约 -8%）**；SA2 覆盖率 **1920/1920 次调用（100%）**，fallback 0、error 0。
- **加载器链路（打包节点）**：`resolve_pattern` 已对真实检查点验证（`zimage_nvfp4`、`zimage_int8`、`krea2_int8`），故意制造的 dtype/检查点不一致会按设计拒绝，端到端加载确认 `wrapped=True` 且 `comfy.ldm.lumina.model` 已重新指向 SA2 attention。

## 8. 说明

- `attention_accel` **默认关闭**（`default`）。既有工作流不受影响。
- SA2 是**内核级**优化：量化权重、GGUF/ConvRot 栈与 LoRA bake 路径均不变。
- SA2 启用时控制台会打印 `[HSWQ SA2] SageAttention2 acceleration installed (...)`，便于事后审计。
