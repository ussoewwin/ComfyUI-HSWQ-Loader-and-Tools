# Release Notes（中文）：v3.7.0 为 ConvRot INT8 与 Hybrid NVFP4 模型（Z Image 与 Krea2）提供完整的 LoRA 与 LoKr 支持，并适配上游 WeightAdapter 架构变革

版本 **v3.7.0** 为 **Z Image（Hybrid ConvRot NVFP4 与 ConvRot INT8）** 和 **Krea2（ConvRot INT8）** 模型带来了**完整、稳健的 LoRA 与 LoKr（LyCORIS Kronecker 积）支持**，全面适配 ComfyUI 官方向 `comfy.weight_adapter`（`WeightAdapterBase`、`LoRAAdapter`、`LoKrAdapter`）体系的底层重构。
代码提交 `0882fce`。完整技术规格书：[md/v3.7.0_COMPLETE_EXPLANATION.md](https://github.com/ussoewwin/ComfyUI-HSWQ-Loader-and-Tools/blob/main/md/v3.7.0_COMPLETE_EXPLANATION.md)。

---

### 1. 解决的故障模式

1. **量化模型上 LoRA 静默失效（完全无效）**：
   - ComfyUI 官方默认的打补丁流程试图对权重执行「反量化 → 叠加 LoRA 差值 → 重新量化回 8bit 或 4bit」。
   - 常见的 LoRA 权重差值极小（仅占权重最大值的 $0.1\% \sim 0.8\%$），远小于粗糙的量化步长（INT8 约为 $\text{amax}/127$，NVFP4 4-bit 更加粗糙），四舍五入重新量化后差值直接被抹除为 0。
   - 此外，`MixedPrecisionOps.Linear` 硬编码了 `want_requant=False`，且 `_dit_quant_lock` 从第 2 步起跳过反量化，导致驻留显存的权重根本无法被更新。

2. **Krea2 LoKr 模型前向计算张量维度不匹配崩溃**：
   - 在 Krea2 上使用社区广泛发布的 LoRA（如 `realism_engine_krea2_v3.1.safetensors` 或 `babegenerator.ink-realism_helper.safetensors`）时，会在 DiT 注意力块前向计算中直接崩溃：
     ```text
     RuntimeError: mm: mat1 and mat2 shapes cannot be multiplied (11363x6144 and 1536x1536)
       at nodes/krea2_convrot_int8/int8_forward.py, line 85, in _add_krea2_lora_residual
       term = torch.matmul(torch.matmul(inp, md.t()), mu.t())
     ```

3. **DisTorch2 / 多卡环境下的残差失效**：
   - 接入 DisTorch2（官方 `comfyui-multigpu` 或 HSWQ 衍生版）时，`ModelPatcher` 的模块克隆操作会切断动态残差属性或替换已打补丁的 forward 函数，导致多卡并行流中 LoRA 被静默丢弃。

4. **Krea2 加载时 UnboundLocalError 崩溃**：
   - `patches/comfy_quant_int8.py` 在加载 INT8 checkpoint 时因作用域变量遮蔽直接报错崩溃：
     ```text
     UnboundLocalError: cannot access local variable 'apply_comfy_quant_int8_patches' where it is not associated with a value
     ```

### 2. 根因分析与技术机理

- **ComfyUI `WeightAdapterBase` 架构重构**：ComfyUI 官方将所有 LoRA 结构抽象为面向对象的适配器类体系。LyCORIS Kronecker 积 LoRA 被实例化为 `LoKrAdapter`，其 weights 元组承载的是 Kronecker 因数矩阵：
  $$\text{weights} = (w_1, w_2, \alpha, w_{1\_a}, w_{1\_b}, w_{2\_a}, w_{2\_b}, t_2, \text{dora\_scale})$$
  其中 $w_1 \in \mathbb{R}^{4 \times 4}$、$w_2 \in \mathbb{R}^{1536 \times 1536}$（$4 \times 1536 = 6144$）。旧代码将 $w_2$ 当作下投影 $[1536, 1536]$，与输入 $[11363, 6144]$ 进行乘算，导致物理上无法乘算的维度冲突。
- **ConvRot 基底一致性**：ConvRot 权重预先经过正交 Hadamard 矩阵 $H$ 旋转（$W_{\text{rot}} = W H^T$）。若直接把未旋转的 LoRA 差值 $\Delta W$ 加到 $W_{\text{rot}}$ 上，会破坏正交基底造成画面严重杂波。必须在原始基底下计算差值并叠加在未旋转的层输出上：
  $$Y = \text{Linear}_{\text{ConvRot}}(x) + \Delta W(x)$$
- **Python 作用域遮蔽**：`load_unet_hswq_weight_dtype` 内部的条件分支中存在同名 import，导致 Python LEGB 规则将模块全局函数识别为该函数的局部变量，当分支未执行时触发 `UnboundLocalError`。

### 3. 加载器现在的处理方式

1. **原生 LoKr 残差提取与分解**：
   - `_extract_lora_residual`（Krea2）与 `_extract_zi_lora_residual`（Z Image）可原生检测 `adapter_name == "lokr"`，安全提取因数矩阵 $w_1$ 与 $w_2$，并支持因子矩阵乘积（$w_{1\_a} w_{1\_b}$ 与 $w_{2\_a} w_{2\_b}$）。
   - 普通 LoRA（`lora`）增加严格的形状断言校验，确保 $\text{mat\_up.shape}[1] == \text{mat\_dn.shape}[0]$。

2. **Kronecker 因数的高效分组张量积前向计算**：
   - 彻底避免在显存中实例化庞大的 $6144 \times 6144$ 稠密矩阵（在 112 个 DiT 投影层中展开需要超过 $8.4\text{ GB}$ 临时显存），HSWQ 利用张量恒等式：
     $$(W_1 \otimes W_2) \cdot \text{vec}(X) = \text{vec}\left(W_2 X W_1^T\right)$$
   - 将输入 $X \in \mathbb{R}^{B \times L \times (q \cdot s)}$ 变换为分组张量 $[B, L, q, s]$（$q=4, s=1536$），执行串联 cuBLAS 矩阵乘法：
     $$H_b = X_{[B, L, q, s]} \cdot W_2^T \quad \in \mathbb{R}^{B \times L \times q \times r}$$
     $$H_c = \left(H_b^T \cdot W_1^T\right)^T \quad \in \mathbb{R}^{B \times L \times p \times r}$$
     $$\text{Term} = \text{Reshape}(H_c, [B, L, p \cdot r])$$
   - 临时显存开销几乎为零，且在 Tensor Core 上以亚毫秒级延迟运行。

3. **零损失浮点残差前向加算**：
   - 底层量化权重（INT8 / NVFP4）在 VBAR/mmap 存储中保持 100% 冻结且 Bit-exact。
   - 极其细微的 LoRA 变化量（$0.01\% \sim 0.1\%$）得到完全保护，不再被量化抹零，使模型同时拥有低显存高采样速度与原版 FP16/BF16 的 LoRA 表现力。

4. **DisTorch2 / 多卡并行无缝衔接**：
   - 绑定的 forward 方法与残差容器在 `ModelPatcher` 克隆后依然保留，确保每张 GPU 独立在其张量/流水线并行切片上计算并叠加精准的浮点残差。

5. **加载阶段作用域修复**：
   - 将 `patches/comfy_quant_int8.py` 内部的 import 别名化为 `apply_krea2_convrot_int8_patches`，消除 `UnboundLocalError`，并增加 `covrot` 拼写变体的自动容错识别。
