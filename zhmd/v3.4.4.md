## 1. 概述

v3.4.4 新增了 **HSWQ Load ConvRot INT8 ControlNet Model**（`HSWQLoadConvRotINT8ControlNet`）节点。

该节点支持在 ComfyUI 中直接加载并运行 **ConvRot / TensorWise INT8 量化 ControlNet 检查点**（如 Qwen Image Fun ControlNet 等），将 ControlNet 权重以 8-bit 精度（`QuantizedTensor` / `TensorWiseINT8Layout`）保持在显存（VRAM）中，并在前向计算时利用 `comfy_kitchen` 的高速 `int8_linear` GEMM 内核与在线激活旋转（`convrot`）执行推理。

同时，该节点具备自动格式探测与向下兼容机制，可无缝加载传统的 **FP16 / BF16 / FP8** ControlNet 检查点，作为 ComfyUI 原生 “Load ControlNet Model” 节点的完全上位替代。

---

## 2. ComfyUI 原生加载器的根本缺陷

在 ComfyUI 原生的 ControlNet 加载流程（`controlnet_load_state_dict`）中，直接加载 INT8 量化检查点会遇到两个核心阻碍：

| 机制 | ComfyUI 原生加载器行为 | 导致的问题 |
|:---|:---|:---|
| **模块图构建 dtype** | `unet_dtype = weight_dtype(sd)` 获取权重类型 | 对于 INT8 量化模型，返回 `torch.int8`。在实例化 PyTorch 模块图时，`operations.Linear(..., dtype=torch.int8)` 会抛出 `RuntimeError: Only Tensors of floating point and complex dtype can require gradients`，导致初始化立即崩溃。 |
| **量化算子注入** | ControlNet 加载路径未提供 `model_config.quant_config`，不传递 `custom_operations` | 即使强行将 dtype 设为浮点类型，检查点内的 `*.comfy_quant` 与 `*.weight_scale` 元数据也会被忽略，权重无法作为量化张量加载。 |

---

## 3. 架构设计与实现细节

`HSWQLoadConvRotINT8ControlNet` 通过以下架构设计彻底解决了上述问题：

```
[ safetensors Checkpoint ]
           │
           ▼
[_has_int8_comfy_quant] ──(未检测到 INT8)──► [ 原生 load_controlnet_state_dict ] (FP16/FP8 完全兼容)
           │ (检测到 INT8)
           ▼
[ model_options 构建 ]
  ├── dtype = torch.bfloat16  (避免 PyTorch INT8 梯度初始化崩溃)
  └── custom_operations = _int8_mixed_precision_ops() (注入 MixedPrecisionOps)
           │
           ▼
[ comfy.controlnet.load_controlnet_state_dict ]
           │
           ▼ (解析 *.comfy_quant & *.weight_scale)
[ VRAM: TensorWiseINT8Layout (8-bit) ]
           │
           ▼ (前向推理)
[ comfy_kitchen.int8_linear + ConvRot 在线激活旋转 ]
           │
           ▼
[ 输出: 标准 CONTROL_NET 对象 ] ──► [ Apply ControlNet 节点 ]
```

### 核心实现组件

1. **元数据自动探测 (`_has_int8_comfy_quant`)**：
   - 遍历 state dict 中的 `*.comfy_quant` 键并解码 JSON 元数据。
   - 当检测到 `format == "int8_tensorwise"` 时，激活 INT8 加载路径；否则自动走原生标准路径。

2. **显式构建 MixedPrecisionOps (`_int8_mixed_precision_ops`)**：
   - 显式构建包含 `QUANT_ALGOS["int8_tensorwise"]` 的 `mixed_precision_ops`，并将其作为 `custom_operations` 传入。
   - 模块在执行 `_load_from_state_dict` 时，各 Linear 层会自动将 INT8 权重与 scale 封装为 `QuantizedTensor`（`TensorWiseINT8Layout`）。

3. **浮点架构初始化 (`dtype = torch.bfloat16`)**：
   - 强制以 `torch.bfloat16` 构建 ControlNet 模块图，确保 PyTorch 模块能够正常完成参数初始化，随后由 `MixedPrecisionOps` 将量化权重正确挂载。

4. **端到端标准集成**：
   - 输出标准 `CONTROL_NET` 对象，与 ComfyUI 原生 `Apply ControlNet` 等下游节点 100% 兼容。

## 4. 特性对比

| 項目 | 原生 Load ControlNet Model | HSWQ Load ConvRot INT8 ControlNet |
|:---|:---|:---|
| **ConvRot INT8 ControlNet 支持** | ❌（初始化崩溃） | ✅（原生支持） |
| **显存（VRAM）占用** | 无法加载 | 8-bit（INT8 保持） |
| **推理 GEMM 内核** | — | `comfy_kitchen.int8_linear` + ConvRot 在线激活旋转 |
| **传统 FP16 / BF16 ControlNet** | ✅ | ✅（自动兼容） |
| **FP8 ControlNet** | ✅ | ✅（自动兼容） |
| **输出格式** | `CONTROL_NET` | `CONTROL_NET`（完全兼容） |
