## ① 现象

一直正常运行的ワークフロー突然报错：

```
[ERROR] !!! Exception during processing !!!
_patch_comfy_kitchen_int8_gemm_fallback.<locals>._safe_cuda_int8_linear()
    got an unexpected keyword argument 'input_act_weight'
```

调用栈最终落在 torch-inductor 编译代码中的 `torch.ops.comfy_kitchen.int8_linear` 调用处：

```
File ".../comfy_ops.py", line 59, in call
    buf0 = torch.ops.comfy_kitchen.int8_linear.default(arg0_1, arg1_1, ...,
        convrot_groupsize=256, input_act=None, input_act_weight=None,
        input_act_eps=0.0, residual=None, residual_scale=None)
...
TypeError: _patch_comfy_kitchen_int8_gemm_fallback.<locals>._safe_cuda_int8_linear()
    got an unexpected keyword argument 'input_act_weight'
```

复现路径为 **Z Image / Lumina2 ConvRot NVFP4 LoRA + USDU**（ComfyUI-HSWQ-Loader-and-Tools `nunchaku_usdu` → `ultimate_sd_upscale` → `comfy.sample`）。

## ② 根本原因

### ②-1. comfy_kitchen 0.2.36 修改了 `int8_linear` 的签名

`comfy_kitchen` **0.2.36**（2026-09-30 安装）同时扩展了算子与 CUDA 后端：

```python
# comfy_kitchen/backends/cuda/__init__.py (0.2.36)
def int8_linear(
    x, weight, weight_scale, bias=None, out_dtype=None,
    convrot=False, convrot_groupsize=256,
    input_act=None,
    input_act_weight=None,      # 新增
    input_act_eps=0.0,          # 新增
    residual=None,              # 新增
    residual_scale=None,        # 新增
) -> torch.Tensor:
```

`torch.ops.comfy_kitchen.int8_linear` 增加了同样的四个参数，且 ComfyUI 本体 `comfy/ops.py`（`linear_input_act`）已改为传入它们。

### ②-2. HSWQ 的回退包装器仍是旧的 8 参数签名

`patches/comfy_quant_int8.py` 中的 `_patch_comfy_kitchen_int8_gemm_fallback()` 会用受保护的包装器替换 `comfy_kitchen.backends.cuda.int8_linear`（即未对齐 K/N 层反量化为 float、避免 `cublas_gemm_int8` 崩溃的回退）。该包装器是按旧签名编写的，转发固定的关键字集合：

```python
def _safe_cuda_int8_linear(x, weight, weight_scale, bias=None, out_dtype=None,
                           convrot=False, convrot_groupsize=256, input_act=None):
    ...
    return orig_cuda_int8_linear(x=..., input_act=input_act)  # 不认识 'input_act_weight'
```

一旦 ComfyUI 本体传入 `input_act_weight=...`，包装器在到达真实内核之前就抛出 `TypeError`。由于该算子被 `torch.compile` 包裹，错误在 inductor 调用处显现。

### ②-3. 为什么只有 INT8 Linear 路径崩溃

`int8_linear` 是 0.2.36 中唯一改变签名的 comfy_kitchen 算子，而 HSWQ 的回退包装器是唯一重新声明该签名的地方。其余 HSWQ 与 comfy_kitchen 的交互均未受影响：

- **NVFP4 / W4A4 路径** 以**关键字参数**调用 `ck.scaled_mm_nvfp4(...)` / `ck.quantize_nvfp4(...)`，多出的参数不会破坏它们。
- **mm / addmm INT8 分派** 保有各自的 `except Exception -> dequantize` 回退，因此 Linear 路径上的包装器 `TypeError` 不会波及它们。

## ③ 修复

`patches/comfy_quant_int8.py` —— `_patch_comfy_kitchen_int8_gemm_fallback()` 第 1 步（`comfy_kitchen.backends.cuda.int8_linear` 补丁）：

1. **接收新参数** —— `input_act_weight`、`input_act_eps`、`residual`、`residual_scale`，外加 `**extra_kwargs`，使将来新增参数也不会再抛 `TypeError`。
2. **仅转发已安装算子实际声明的参数** —— 包装器一次性探测真实签名：

   ```python
   _orig_param_names = set(inspect.signature(orig_cuda_int8_linear).parameters)
   ```

   仅当参数名存在时才加入调用。因此旧 `comfy_kitchen`（无这些参数）与新 `comfy_kitchen`（0.2.36+）都能用同一份代码运行。
3. **保持反量化回退与本体一致** —— 未对齐 / 非 CUDA 回退现按真实算子的方式应用 `input_act` 与 `residual`（经由 `ck_cuda._apply_input_act` / `ck_cuda._apply_residual`，并做保护：助手不可用时保持张量不变）。回退被归并为一个 `_dequantized_linear()` 闭包，对齐路径与异常路径共用。

其余行为不变：**INT8 权重仍以 INT8 常驻 VRAM**；仅未对齐 / 非 CUDA 路径反量化为 float，与以往完全一致。

## ④ 已执行的验证

- **算子级（真实 0.2.36）**：以完整新参数集与最小关键字分别调用 `torch.ops.comfy_kitchen.int8_linear` —— **均成功**。
- **包装器级（桩 CUDA 后端）**：修补后的包装器正确转发 `input_act` / `input_act_weight` / `input_act_eps` / `residual` / `residual_scale`，对未知的未来关键字不抛错，且旧式调用仍可用。
- **范围普查**：枚举全部约 45 个 `comfy_kitchen` 算子 schema —— 仅 `int8_linear` 签名变化；HSWQ 引用的所有 `comfy_kitchen.tensor` / `comfy_kitchen.backends.cuda` 符号在 0.2.36 中仍存在；HSWQ 补丁模块在 0.2.36 下可正常 import。
